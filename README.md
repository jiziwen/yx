## 本地启动

要求 Node.js 20.19+、pnpm 11.25、uv（自动选择 Python 3.12）。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

启动脚本会同步后端锁定依赖、执行 Alembic 迁移，再启动 API、独立媒体/Agent Worker 和两个前端。开发数据库与照片在忽略目录 `.data` 中；参考工程不参与构建。Ctrl+C 停止这次启动的所有进程。

- 用户端：[http://127.0.0.1:5273](http://127.0.0.1:5273)
- 独立后台：[http://127.0.0.1:5274](http://127.0.0.1:5274)
- API 契约：[http://127.0.0.1:8100/docs](http://127.0.0.1:8100/docs)

用户在弹窗内输入测试手机号，点获取验证码；开发验证码直接显示，不发送短信。管理员为 `admin`，本地默认密码为 `yingxu-dev-admin`，`ADMIN_PASSWORD` 只用于显式开发模式下的首次初始化，不会覆盖已经保存的凭证。数据库模式通过受控 CLI 开通管理员，见下文。用户和管理会话分别签名，凭证只写 HttpOnly Cookie。

默认图片插件生成明确标记的开发卡片，**不生成真人照片**。M2.5 工作室采用左侧聊天、右侧编辑与结果；聊天可整理四种创作需求，右侧也可全程手动操作。补齐本次输入后自动准备右侧确认卡，点击一次确认才生成。人物模式需声明授权并选参考，文字模式无需照片。双人项目需要两个人物分别提供参考照。试用按账号和活动版本仅领一次。

## 可插拔与配置

- 业务模块：`services/backend/resources/application.yaml` 的 `modules` 声明可信 Python 入口、启停和依赖；启动时验证循环、缺失依赖与重复 ID。关闭模块不删除其数据库历史。
- 模型网关：同一配置中的 `providers` 和 `routes` 声明适配器、版本、能力、超时与密钥环境变量；内置开发图片、开发 LLM、私有本地存储，以及未启用的 HTTP 兼容图片/对话候选适配器。
- 生成目录：`services/backend/resources/catalog.yaml` 声明版本化风格、画幅、数量上限。方案冻结具体风格、输入、权益和供应商配置摘要。
- 主题：`apps/web/src/themes/<id>/manifest.ts` 声明 token、图片、布局、Hero、Intro；注册表自动发现目录。新增主题不需要修改业务页面。
- 前端功能：用户端 `apps/web/src/modules/*/manifest.tsx`、管理端 `apps/admin/src/features/*/manifest.tsx` 自动注册路由与菜单，并按服务端模块依赖过滤。
- 功能开关：试用与工作室创作对话已启用；Agent 只整理草稿，确认生成沿用业务 API。创作与客服、知识库和人工接管已接入；赠品和支付继续后续阶段。详见 [M2 创作 Agent](docs/M2创作Agent.md)。

配置变更通过部署重启生效；供应商配置变化后旧待确认方案会被拒绝，必须重新保存确认。配置文件不能放密钥，插件入口只允许运维人员维护。详细示例见 [插件接入](docs/插件接入.md)。

## 工程与验证

```sh
pnpm check:m0  # Docker + Chromium：完整 M0 工程验收，失败即停并记录报告
pnpm check:m1  # 同上并检查 302 联调准备；工程契约通过不代表真实质量通过
pnpm check:m2  # M2 工程入口
pnpm check:m25 # 当前全量工程入口，含双入口/视觉/补偿/隔离实验与原M2回归
pnpm lint
pnpm typecheck
pnpm build
pnpm test
pnpm test:client
pnpm api:generate
pnpm api:check
# 可选：需要 Docker，用临时 PostgreSQL 验证迁移、双人闭环与并发确认
pnpm test:postgres
pnpm test:redis
pnpm eval:prepare  # 仅校验样例定义，不调用真实模型
pnpm eval:preflight # 只检查供应商配置/凭证存在/授权清单，不发付费请求
# 浏览器测试使用 5373 / 5374 / 8200 和临时数据库，可与 pnpm dev 并行
pnpm exec playwright install chromium
pnpm test:e2e
```

M0 验收清单见 [M0 验收](docs/M0验收.md)。本地报告为 `.data/m0/last-run.json`；CI 使用同一命令，实际远程 CI 结果仍以仓库运行记录为准。

默认端口占用时会在迁移前退出，不会停止其他项目。可通过 `YINGXU_WEB_PORT`、`YINGXU_ADMIN_PORT`、`YINGXU_API_PORT` 指定另一组端口。

受控管理账户开通（先迁移，再在受控终端输入密码，不把密码放进命令行）：

```sh
cd services/backend
uv run python -m app.cli create-admin --username ops --display-name 管理员
```

设置 `ADMIN_AUTH_MODE=database` 后只接受已开通的密码摘要。生产必须关闭开发短信登录、选择 Redis 认证状态（`AUTH_STATE_BACKEND=redis`）并配置独立会话密钥。管理员 Cookie 使用单独 TTL，默认 1 小时。验证码只有带密钥摘要进入存储，Redis 验证过期、限次和消费操作为原子脚本；实际短信发送按用户决定延期，本地继续开发验证码。

后端可单独运行：

```sh
cd services/backend
uv sync --frozen
uv run alembic upgrade head
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8100
# 另一终端
uv run python -m app.workers.local
```

`apps/web` 与 `apps/admin` 独立构建；`packages/api-client` 共享由 OpenAPI 生成的类型。前端代码不保存敏感 localStorage 数据，只保存外观主题。数据库、私有文件和模拟登录均不能作为生产接入方案。

## 当前边界

管理后台新增[次数发放](docs/后台次数发放.md)：`/entitlements`选择用户和项目、填写次数/原因，查询人工补发及试用发放记录；重复提交及断线重试不重复增加次数。只增加可用次数，图片仍由用户确认生成。

真实图片与 creative Agent 已连通后台选择的 302 模型；身份质量与成本评测、客服/RAG、赠品渲染、售后与支付尚待对应阶段实现。短信和 S3 按用户决定延期。生产启动拒绝假供应商、开发登录、弱默认密钥和 SQLite；当前不是可对外上线的完整产品。

数据库先实现 15 张本阶段使用的表，包含独立幂等记录；并未一次性创建设计中的 25 张表。生产采用 PostgreSQL；SQLite 仅降低本地启动门槛。Celery 投递与维护入口已提供，Redis 集群/高并发/备份恢复尚未验收。
