# 陪伴式摄影师体验

`DreamHero.tsx` 是各主题可复用/替换的正式首页构图。`atelier.css` 是与独立原型共享的布局，保留原型回退色；正式 `production.css` 将 manifest 色彩 token 映射到语义色，禁止按 themeId 在业务页硬编码颜色。

`StudioGuide.tsx` 通过生成的会话/Run API 接入后台 LLM，展示真实模型、阶段、追问和字段级草稿卡；最近对话随项目持久化，失败保留输入。用户明确提出的可撤销修改自动同步右侧；额外推荐仍需点击采用。草稿或需求版本已变化时禁用旧建议。旧 guide.ts 已移除。摄影师名称在 `src/config/experience.ts`，chat_enabled、模型、编排与预算来自后端，这里不接收密钥或供应商地址。

`useStudioProject.ts` 沿用项目、人物、资产、提案、Job 和权益 API，活跃任务轮询真实状态。`StudioResults.tsx` 只显示私有作品、真实取消与下载；选片仅在当前页保留。`ui.tsx` 提供共用的抽象 AI 头像，不涉及业务状态。

`pages/StudioPage.tsx` 持有共享表单和冻结提案确认。页面以 projectId 而非 themeId 为实例边界。保存使用按请求体保留的幂等键；确认使用按 approval_id 保留的幂等键。草稿修改、项目修订或其他页面的新版本出现时，不能误执行旧确认卡。后台刷新不会自动覆盖本地草稿；显式载入最新版本可能丢弃草稿时先提示。

首页想法保存在应用上下文内存，项目创建后绑定到 projectId，再进入该项目初始草稿，不写 URL/history/localStorage。退出登录清除入口想法；正式保存后补充要求随提案持久化。敏感数据的清理与授权以服务端为准。

验证入口：`pnpm test:e2e` 覆盖登录后想法带入、引导不自动保存/执行、窄屏、主题切换保留草稿与生成风格、草稿改动禁用旧确认，以及真实测试卡交付；`pnpm check:m0` 执行完整工程回归。真实 LLM 会话、Run、工具、预算与评测仍按开发文档 M2 接入后端网关。

## V1.3 四种创作方式

`creationModes.ts` 提供体验文案；可用性、限制和套系来自后端目录。`creationDraft.ts` 管理草稿、用途和能力提示，`StudioCreationPane.tsx` 以紧凑素材入口和原生弹框呈现操作，`StudioDialog.tsx` 管理焦点与关闭；`studio.css` 提供已确认双栏布局，`creation.css` 仅保留首页入口与灵感库样式。旧体验原型、重复素材表单和旧工作室样式已移除。

底图、人物参考、风格参考按用途选择；已保存素材数量与本次输入数独立。`StudioPage` 保存显式输入，由后端编译逐镜头任务并报价。相同项目切换主题不重建草稿；保存或上传中禁止修改，草稿/项目版本变化使旧确认卡失效。作品列表与素材查询合并，使新作品可立即作为下一轮底图。

V1.7：ProjectMemory.tsx 展示当前确认要求和待确认建议，显式 PUT 才保存；多窗口版本变化保留编辑并要求载入最新，隐私代次变化则关闭旧编辑。ToolObservations.tsx 读取服务端查询结果卡和观察时间，不从 LLM 文本解析次数/状态。StudioGuide 向消息 API 携带 memory revision，并阻止基于旧记忆的提案写入。长期要求不会自动改变当前草稿或已冻结方案。

V1.8：useConversationStream 管理订阅、恢复和合并重读，StudioGuide 保留活跃 Run 低频校准；ProposalChanges 对比冻结原草稿与建议。通知不直接写入 Query 业务对象，旧连接/隐私代次的迟到响应不可恢复已清空内容；尚无 token 逐字流。

V1.9：replyStream.ts 校验和合并临时累计前缀，useConversationStream 接收 message.delta；RunView.reply_preview 可恢复当前前缀。StudioGuide 区分正在回复气泡和最终提案，画布提示放在历史前方以保证新回复可见。临时文字不自动确认/保存或执行生成，最终仍靠权威快照恢复。

V1.10：新增配置化创作需求卡（用户明确确认才保存）、消息 cursor 分页与阅读位置保留、带原话来源的只读历史查询。替换/删除要求后旧记录不再供 Agent 检索；图片仍须用户确认。配置与验收见 [创作需求卡与历史管理](../../../../../docs/M2创作需求卡与历史管理.md)。

V1.11：M2全量功能已补齐：知识导入/索引/发布/指南、混合RAG与授权引用、独立客服与人工接管、员工权限、公开Run Step及精确Release/固定评测。图片仍须用户确认；主题/网关/工具可配置、可插拔。统一工程检查 `pnpm check:m2`，真实重复抽样与人工质量批准单独记录。入口和当前验收见[完整M2说明](../../../../../docs/M2完整交付与验收.md)。


## 2026-10-26：精简双栏工作室

左侧只保留对话与添加照片入口，右侧显示四种模式、当前模式的必要素材、画布、画幅/张数和唯一生成按钮。素材与高级设置按需打开弹框；记忆、分析和只读来源按需展开。人物参考、底图、风格参考分别选择和上传，切换到编辑或文字时不把其他用途的图片夹带给模型。聊天仍通过受控Agent/Run更新同一私有草稿，迟到提案、草稿冲突及隐私屏障保留。

右侧两个页签拥有完整独立的内容区：`创作画面` 包含模式、素材、创意、画幅/张数、建议和生成确认；`作品与进度` 只包含真实任务、作品及作品操作。切换页签保留草稿和临时选片，不新增图片任务。确认生成后进入作品页；从作品继续修改、聊天应用明确创作要求或添加照片时返回创作页。`StudioCreationPane` 不接收作品插槽，避免把结果列表夹在创作控件中间。

作品区使用紧凑网格和完整画面的缩略图，点击打开原生大图弹框，支持左右切换、方向键、Esc和焦点恢复。卡片保留喜欢、下载、继续修改；分析、讨论和质量反馈集中在预览中。已完成任务记录默认收起，正在创作的任务单独显示。聊天用户消息仅保留文字气泡，外层容器透明且无额外内边距。

任务持续轻量轮询，避免确认后读到短暂旧空列表就停止更新；作品、素材和权益使用稳定查询键，并在任务状态变化时同步刷新。`AssetView.source_job_id` 用于准确判断成功任务的交付是否已显示，缺失作品最多补查30秒，现有缩略图保留。`studio-results.spec.ts` 以旧任务列表和晚一次出现的作品列表验证无需手动刷新，以及大图操作返回聊天编辑的流程。

`reconciliation_required` 同样视为在途任务，继续两秒轮询，不计入“未完成”。下载结果受阻时显示“正在获取生成结果”，其他不确定状态显示核对中；查询确认在途后清除旧错误，只有实际交付后才显示成功。

画幅默认 `auto`：同款每个镜头与编辑底图从服务端真实尺寸约分，分别冻结到 `items[].aspect_ratio`，原始像素尺寸冻结到 `items[].size`。人物照和风格参考不决定画幅，无底图时用3:4。用户显式选择后保持覆盖，直到主动恢复auto；16:9和9:16纳入目录、设置表单与适配器尺寸映射。尺寸不设白名单，常用比例仅作为快捷选项；聊天可指定任意比例或宽x高像素尺寸，原图尺寸和用户指定尺寸直接发送给模型接口，不做16倍数、面积或边长限制。历史方案与已确认任务仍使用冻结参数，后台已启用模型的能力变更继续走现有候选/证据审核流程。

生图编译规则为 `creation-v5-zh`：系统补充的指令均为中文，只包含画面要求及必要的图片序号、人物位置；不把聊天操作说明、套系标签或内部ID写入提示词。工作室通过公共目录的 `creation_prompt_policy_hash` 核对未确认卡，规则升级后自动准备新卡；已确认任务及历史调用保持原始证据。

验收使用隔离数据库和开发模型：`creation-modes.spec.ts`、`m25-studio.spec.ts`、`creation-intents.spec.ts` 与后端 `test_studio_ratios.py`。包含四模式交付、刷新恢复、唯一确认、私有风格图片、逐镜头画幅、手动覆盖及窄屏布局；不向付费模型发送测试图片。
