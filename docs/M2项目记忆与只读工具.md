## 使用方式与确认边界

- 对 Lumi 说“请记住不要头纱”后，Agent 可以提出记忆建议。只有点击“确认记住”才保存；普通聊天、写入草稿或模型说“记住了”均不会自动保存长期记忆。
- 聊天区上方“项目记忆 → 管理”可查看、编辑、清空要求。每行一条，默认最多 12 条，每条 160 字。清空编辑框后还需点击“确认保存记忆”。
- 之后每轮上下文都会保留当前有效的确认要求，不依赖最近几轮聊天。新提案会保留这些原话约束；完整要求超过 notes 的 1000 字上限时，需先整理要求，不能静默丢弃。
- 删除或清空要求后，更早聊天不再进入后续整理，避免从旧对话带回已忘记的要求。历史聊天仍可查看，清空记忆不是删除整个聊天记录。
- 记忆不修改当前表单、已保存或已确认的方案，也不是素材授权或执行许可。生成仍为“写入草稿 → 保存正式提案 → 用户确认”。记忆变化后，基于旧记忆的未应用建议不能覆盖新要求。
- 可以直接问“还有几次”“现在生成到哪了”“为什么失败”。Agent 调用受控工具后，展示带查询时间的事实卡。它是观察时刻的快照，不是实时百分比或完成时间承诺。

要求冲突时 Agent 应先追问，不能擅自删除用户确认的记忆。用户也能在管理入口直接编辑，无需依赖模型提取。

## 已实现的工具

| 名称 | 参数 | 结果 | 权限 |
| --- | --- | --- | --- |
| get_entitlements | 无参数 | 当前项目 available / reserved / consumed | creative / 当前拥有者项目 / 只读 |
| get_job_status | 可选 job_id | 全项目状态计数、最近 5 项或指定任务、公开失败分类 | 同上，指定任务也须属于当前项目 |

任务状态直接来自业务 Job。供应商返回失败但没有细节时只说明公开分类；待核对保持“结果未确认、次数仍预占”，不能说已经退款或可以直接重发。工具不访问上游任务接口，不创建/取消媒体任务，不领取试用，不预占、结算或退款。未知错误不返回堆栈、供应商原文、接单凭据、对象键或下载链接。

工具返回 id、名称/版本、ok/error、observed_at、脱敏 data/error_code；最终回复必须引用本轮全部查询来源。UI 的事实卡直接读取服务端结果，不解析模型文字里的数字。查询失败时显示明确失败，不能用历史数字或固定成功话术补齐。

## 配置与插件契约

`resources/application.yaml` 新增可独立停用的 project_memory 模块。`agent.memory_enabled` 控制长期要求注入，`memory_max_items` 上限可调至 1–12；停用保留历史数据。历史聊天与长期要求是两个来源，停用记忆不等于删除聊天。

`agent.tools` 通过 name、entrypoint、enabled 注册可信服务端插件；每项配置 timeout_ms（默认 2000）、max_output_chars（默认 5000）。浏览器和模型不能指定入口、URL 或登录身份。插件必须声明 name/version/title、role=creative、scope=current_project、read_only=True、requires、Pydantic input_model/output_model，并实现 `read(app, db, scope, arguments)`。同名或可写插件在启动时拒绝；新增供应商无需改工具业务逻辑。

Scope 的 user_id/project_id/privacy_epoch 由 Worker 从 Run 与项目注入；模型 arguments 带 user_id/project_id 等额外字段会被拒绝。配置停用、插件配置或版本变化后，排队轮次也不能借冻结入口继续绕过停用。

数据库层附加保护：PostgreSQL 使用只读事务及 statement_timeout；SQLite 使用 query_only、busy_timeout 与查询进度中断，并在归还连接前恢复。插件正常的 SQL 写入会被拒绝。入口仍是部署者维护的受信任代码，不开放任意代码、网络或文件工具。

默认每 Run 最多 3 次 LLM 调用、4 次工具尝试；单次工具请求最多 2 项。无效参数和失败尝试也计数；同一 Run 的相同名称/参数不重复读取。JSON/来源校验最多修正一次，所有步骤共用入队起算的 90 秒总期限。新查询需要后续新消息，Agent 不后台持续轮询。

上下文默认 12000 字符，其中给工具结果预留 4000；模型窗口默认 64000 tokens，继续预留配置的输出预算与安全余量。当前消息、表单和有效记忆为必要信息，历史只按完整轮次裁剪；必要信息或工具结果超限明确失败。配置更小窗口模型时同步调整预算。

编排仍为可替换 LangGraph 短图：理解 → 校验 → 可选只读查询 → 根据结果回复/提案 → 提交；参考[官方流程与 Agent 编排说明](https://docs.langchain.com/oss/python/langgraph/workflows-agents)。不依赖模型供应商原生工具 SDK，兼容当前结构化 JSON 网关；未增加写工具或隐藏执行路径。

新增迁移 ffba47dfea56：project_memories 当前版本表；AgentRun 新增 memory_revision、tool_calls、tool_trace_json；Message 新增 memory_suggestion_json、observations_json。旧 Run 的新字段回填 0/空数组，旧聊天保留。记忆操作审计只记录版本与条数，不复制正文。

确认记忆由用户身份和项目锁保护，模型没有写入工具。并发编辑使用 revision，授权代次不同立即拒绝；记忆变化不增加 brief_revision，不使已确认的图片任务改用新条件。进行中的 Agent 在调用/查询/最终提交前复核记忆版本，变化后以 MEMORY_CHANGED 结束，不发布迟到提案。前端也阻止旧建议覆盖新版本。

撤销人物/素材后，旧代次记忆、消息、候选建议和查询证据立即不可见且不进入模型。维护进程清除旧记忆正文、Run 上下文/工具结果及 Message 附加内容；不因物理清理再次改变有效记忆版本。编辑弹窗发现授权代次变化会关闭旧编辑内容。完整账户/项目删除仍属于后续范围。
