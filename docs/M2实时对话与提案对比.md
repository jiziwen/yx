## 用户可见行为

- 聊天顶部显示连接状态。Agent 排队、理解需求、查询项目记录、整理回复等阶段取自已经提交的 Run；最终回复及提案经服务端校验提交后显示。
- 网络中断自动退避重连；回到前台或重新进入工作室时同步已保存对话。不会因重连重新提交需求或重试 LLM。
- 提案逐项显示“原草稿 → 建议修改”，原值来自发送该需求时冻结的 draft_context。沿用字段折叠展示。可见对比不代表已经应用。
- 用户后来修改草稿、项目资料或确认记忆后，旧提案仍不可覆盖新内容。仍需明确“写入草稿 → 保存提案 → 确认生成”。
- 退出、账户封禁、项目删除导致的权限失效会停止旧连接并清除本页对话；隐私代次变化清空旧内容后重新同步。

本批提供真实阶段和已提交消息的通知，不提供供应商 token 逐字输出，不显示隐藏推理，也不保证展示每一个短暂阶段。历史只读事实卡仍标明观察时间，不会被悄悄改写成实时数字。

## 接口与通知语义

`GET /api/v1/web/projects/{project_id}/conversation/events`，使用既有 HttpOnly 用户 Cookie。普通用户只能连接自己的项目，管理 Cookie 不替代用户身份。未授权返回既有 JSON 错误信封，不先发送 ready；可独立停用并回退快照。

| 事件 | 含义 |
| --- | --- |
| stream.ready | 鉴权通过、数据库观察基线已建立；客户端此时再次读权威快照 |
| message.committed | 当前隐私代次最大消息 seq 改变；resource_revision 为该 seq |
| run.updated | 有界最近 Run 的已提交状态/阶段/调用计数变化；只触发快照失效 |
| stream.sync | 项目版本、生命周期、记忆版本或开关变化；重新同步 |
| stream.heartbeat | 连接存活控制事件 |
| stream.reset | 隐私代次改变；关闭连接、清空旧内容并重新读取项目 |
| stream.revoked | 当前 Cookie 或项目权限不再有效；关闭并清除本页会话 |
| stream.reconnect | 到达连接寿命上限；重新订阅并同步 |

信封为 schema_version=1、event_id、resource_id、occurred_at、可空 resource_revision、payload。业务通知没有消息正文、提案内容、工具结果、供应商响应或私有素材地址。没有持久化事件日志，不支持 Last-Event-ID 回放；event_id 不是可重放游标。

客户端将 ready 之后的变更合并为一个 dirty 位：快照读取期间收到通知会在当前读取结束后再读一次。通知不直接追加消息或覆盖 Run，所以无需用缺少数据库 revision 的 Run 通知合并业务内容；重复/迟到通知只增加一次有界重读。最终顺序仍由快照中的会话 seq 确定。

服务器先读取观察基线，再发 ready，再比较数据库事实，覆盖“建立连接与快照读取之间完成”的竞态。消息可能在两次采样之间完成多个阶段，允许合并通知。即使连接健康，活跃 Run 仍每 15 秒读取快照，防止漏通知；终态取消活跃任务校准，空闲每 60 秒仅同步项目/会话变化。SSE 失败时，活跃快照退避至 4–15 秒，空闲每 30 秒；重连退避 1/2/4/8/16/30 秒，35 秒无任何事件会重新连接。

页面隐藏时关闭连接，回到前台再订阅；前台/网络恢复也同步快照。只保留当前组件的连接，卸载清理所有监听与定时器。旧连接、旧隐私代次的迟到回调和消息/取消响应不能恢复已清空的内容。服务端每次采样重新校验签名 TTL、账户状态、会话版本、项目归属和隐私代次。

## 配置、部署与兼容

`services/backend/resources/application.yaml`：

```yaml
conversation_stream:
  enabled: true
  poll_seconds: 2
  heartbeat_seconds: 15
  max_connection_seconds: 240
```

Pydantic 启动约束：poll_seconds 0.5–10，heartbeat_seconds 5–20，max_connection_seconds 30–600。配置在启动时读取；停用通知后快照与发消息 API 照常工作。此配置不进入 LLM 冻结预算，也不要求特定模型或供应商支持流式协议。

本批利用数据库作为跨 API/Worker 的权威变化来源，不增加 Redis Pub/Sub 依赖。每个连接每次只读取项目、当前记忆版本、最大消息 seq、最近最多 30 个 Run 的轻量状态列；数据库会话在等待下一次采样或网络发送前释放。它是当前规模的数据库通知实现，仍需后续连接容量/数据库负载压测；不是高容量事件总线。媒体 Job/作品通知暂未接入，继续既有任务轮询。

用户端 nginx 对 API 使用 HTTP/1.1、关闭代理缓冲/缓存，120 秒读取超时覆盖最长 20 秒心跳。响应包含 text/event-stream、Cache-Control:no-store、X-Accel-Buffering:no；其他反向代理也需采用相同策略。协议参考 [MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。

数据库模式没有变化，无新增迁移；迁移头仍为 ffba47dfea56。旧页面可继续读取原会话快照，原消息提交/取消/审批协议兼容。升级前备份 `.data/agent-realtime/main-before-v1.8.db`。
