# 可插拔模块与配置

## 业务模块

创建 `services/backend/app/modules/<name>`，提供 API、业务服务、数据模型和职责 README。`manifest.py` 的公开契约为：

```python
from app.core.plugins import Module
from .api import router
module = Module(id="example", version="1.0.0", requires=("identity",), router=router)
```

在 `resources/application.yaml` 的 `modules` 添加 `entrypoint: app.modules.example.manifest:module` 与 `enabled: true`。依赖没有启用、依赖循环、重复 ID 都会阻止启动。模块历史表由 Alembic 维护，禁用时不移除历史。

新表须在 `app/core/models.py` 注册，并生成显式 Alembic 迁移。身份、资源授权与审计必须通过业务依赖校验；不能把插件当作权限绕过机制。

前端新增 `src/modules/<name>/manifest.tsx`，导出 `Feature[]`，声明 `requires` 与可选 `flag`。注册表自动发现并同时生成菜单和路由，页面可用性与后端实际模块一致。管理端同样通过 `apps/admin/src/features/*/manifest.tsx` 自动注册运营功能，并验证对应后端模块是否已安装。

## 模型与基础设施网关

协议位于 `app/integrations/contracts.py`，当前提供 image、llm 和 storage。插件构造函数为 `(options, settings)`；请求参数不能覆盖环境凭证。

```yaml
providers:
  custom-image:
    enabled: true
    kind: image
    version: '1'
    release_status: candidate # 真实样本与成本验收后才可设为 validated 用于生产
    entrypoint: app.integrations.custom:CustomImage
    capabilities:
      reference_images: true
      operations: [text, reference, edit]
      max_input_images: 6
      max_reference_images: 4
      max_style_images: 2
      max_subjects: 2
      aspect_ratios: ['3:4', '4:3', '1:1']
    options:
      api_key_env: CUSTOM_IMAGE_API_KEY
      timeout_seconds: 90
routes:
  image: custom-image
```

以上是新增片段，不是完整可运行 application.yaml。保留其他 providers/routes/modules。将凭证写入后端环境变量，不放在 YAML。必须禁用开发适配器才能通过生产启动校验。

`generate(ImageRequest)` 返回 `ImageResult` 字节数据。失败用 `ProviderFailure(code, unknown=False)` 表达供应商明确拒绝，用 `unknown=True` 表达可能已接受。不允许适配器自动重试带副作用的生成；数据库 Job 决定是否可再次提交。旧方案冻结供应商配置哈希，待确认方案在默认路由变动后必须重新保存并确认。已经确认的 Job 使用冻结供应商，只要原适配器及版本配置仍保留，更换默认路由不会切走旧任务。

内置 `CompatibleImage` 为文字 `/images/generations`、有图 multipart `/images/edits` + `b64_json` 的候选实现，`CompatibleLLM` 为 `/chat/completions` JSON 输出候选实现。它们不下载任意结果 URL。上游能力与尺寸语义必须逐家验证，不保证所有“兼容”供应商都能直接接入。302 凭证及真实图片/对话链路已验证，单/双人效果和账单成本仍待验收；兼容协议不代表所有供应商均已通过。

V1.4 新增 `AsyncImageProvider`：`submit` 只返回 `ImageSubmission(task_id)`，`lookup(task_id, request_key)` 返回 pending/succeeded/failed/cancelled/unknown。Worker 在接单凭据提交到数据库后才能查询；查询不得调用新的生成。`ImageResult` 可提供数值 usage、确认费用微单位与币种，不提供即未知，不能用估算填充。同步/异步最终交付共用授权、Asset 和权益事务。

已提供默认关闭的 `AI302Image`，使用 302.AI 统一异步接口和角色排序的 data URL 输入。结果限受控的公共 HTTPS 文件主机，不传认证头、不跟随重定向并限制大小。模型按 text/reference/edit 配置；详见 [M1 供应商与任务恢复](M1供应商与任务恢复.md)。生产图片插件还必须声明 `release_status: validated`；此标记需要真实验收依据。

`runtime.account_scope/max_in_flight/requests_per_minute/poll_seconds/failure_threshold/cooldown_seconds` 声明共享账号保护。同账号模型的共享限额不一致将拒绝启动。全局 `queue_limits` 限制批量、用户和总待处理量；这些规则由服务端执行。修改账号范围前必须排空在途/未知任务，不能借配置变更绕过旧尝试槽位。

新增 embedding、SMS、rendering 等集成时，按相同方式增加明确的协议和网关类别，不把各种插件塞成同一种无约束 `execute(dict)`。尚未实现的类别不能提前在运营界面标记为已接入。

## 新增主题

后台模型发布补充：302 模型可通过 /models 配置并即时发布，不再要求改 YAML/重启。运营只接受白名单模型名、接口类型、质量/输出预算、操作和图片能力，不接受密钥、URL 或插件入口。model_releases 保存不可变历史定义，API/Worker 读取统一发布指针，已确认任务保留旧插件；LLM 改动不会无故改变图片插件 ID。原生 GPT 插件 AI302GPTImage 显式发送 quality；统一图片插件仍可用于其他模型。详见 [后台模型配置](后台模型配置.md)。

复制一个 `apps/web/src/themes/<id>` 目录，提供：

- `manifest.ts`：唯一 ID、名称、顺序、资源版本、token、样片、Hero/Intro 的 lazy import。
- `Hero.tsx`：自定义首页视觉组件，或复用 `../../features/atelier/DreamHero` 的梦幻构图；只负责展示和开始入口。组件接收 `theme`、`onCreate(theme)` 与可选 `onStart(brief)`，不得在主题组件中创建 Job 或调用供应商。
- `Intro.tsx`：氛围组件；可跳过、Escape、计时和减少动态效果由 `ThemeProvider` 统一控制。
- `theme.css`：主题扩展样式，基础颜色仍取 manifest 的 token。

自动注册使用 Vite `import.meta.glob('./*/manifest.ts', { eager: true })`，不需要改业务组件。manifest 轻量同步加载，Hero/Intro 通过 lazy 加载。`enabled: false` 可隐藏某个主题；默认主题不可用时回退到已启用主题，全部禁用时明确报错。样片放在私有资料之外的公共资源目录，并记录素材授权。

主题 ID 与风格 ID 独立。新增可生成风格需要另外修改后端 `resources/catalog.yaml` 并标版本；普通切主题不会更改项目、参考照片或当前方案。

V1.2 可在 manifest 增加以下可选展示配置，缺省时由共享 Hero 使用安全默认值：

```ts
atelier: {
  headline: ['把心动的模样，', '拍成一场梦。'],
  subtitle: '不必懂镜头，也不用想好答案。',
  coverImage: '/images/my-theme.webp',
  coverPosition: '70% center',
  canvasPosition: '50% 20%', // 宽画布单独配置焦点，避免裁掉人物面部
  secondaryImage: '/images/my-secondary.webp',
  palette: ['#d4c6df', '#eed8ce', '#c6cbbd'],
}
```

正式页面从主题的 `--bg`、`--surface`、`--surface-up`、`--text`、`--muted`、`--accent`、`--button-bg`、`--accent-ink` 和 `--scene-secondary` 等 token 派生 `--at-*` 语义色；不需要在业务 CSS 追加某个 theme_id 的颜色分支。按钮底色与文字应保持可读对比。改动视觉资产或 token 时更新 manifest 版本；这不等于修改后端生成风格版本。

`apps/web/src/config/experience.ts` 声明默认主题和摄影师显示名称。V1.6 正式 StudioGuide 已通过后端项目会话接入 LLM，旧 guide.ts 已移除。开关来自服务端 chat_enabled 与模块装配，编排/预算来自 YAML 的 agent，模型来自后台发布或网关路由；不可把密钥或 base_url 放入体验配置。前端主题仍从 manifest token 取色。详情见 [M2 创作 Agent](M2创作Agent.md)。

工作室实例只以 projectId 为边界，不以 themeId 作为 key。改变外观须保留表单、引导便签、临时选片和待确认动作键；风格选择仅改变本地草稿，保存后由后端冻结适配器/版本/配置哈希。正式结果只读 Job 和私有 Asset；不能导入 `experience-preview` 的示例人物或定时器。

当前同一浏览器会话首次入场约 2.8 秒，可跳过，减少动态效果时不播放。主题切换使用约 0.4 秒颜色过渡；尚未做每主题 0.9 秒复杂转场或设备性能分级。


## V1.3 套系与模型能力

`catalog.yaml` 可配置 `enabled_modes`、`upload_limits`，每个 style 的 `enabled`、`description`、`shots`。镜头声明 `id/name/file/position/subject_slots/development_only`；file 相对于目录文件所在目录，只能指向该目录以内的文件。镜头启动时规范化并计算摘要，后端返回安全的公开预览地址。当前内测样片不代表已取得供应商输入授权，生产过滤 development_only 镜头，真实插件也不能使用这些镜头。新增正式素材需记录来源及生成用途授权。

`image_routes: {text: custom-text-image, edit: custom-edit-image}` 可按底层操作选择插件，`reference` 表示人物参考生成；缺省沿用 `routes.image`。前端从 `/web/catalog` 取得方式与实际限制，不向浏览器暴露 options、密钥或上游 URL。禁用方式或插件将关闭入口；后端校验不能由 UI 替代。

图片能力必须声明 `operations/max_input_images/max_reference_images/max_style_images/max_subjects/aspect_ratios`。`max_input_images` 统计本任务底图、人物参考和风格参考的总和；套系不会把所有底图合并到一项任务。兼容插件可通过 `options.size_by_aspect_ratio` 配置经过验证且与画幅一致的像素尺寸。

`ImageRequest.operation/input_roles/subject_bindings` 描述受控操作、图片顺序用途与人物对应。真实图片适配器必须正确解释这些信息；协议兼容与 UI 能操作均不代表身份效果已达标。配置调整后旧待确认方案须重新保存，已确认任务继续使用冻结供应商与配置摘要。接入细节见[四种创作方式接入](四种创作方式接入.md)。

## V1.7 记忆与只读工具

project_memory 是可停用业务模块，agent.memory_enabled/memory_max_items 控制要求注入；agent.tools 按 name/entrypoint/enabled 注册可信只读插件及结果/时限。插件声明 role/scope/read_only、模块依赖、Pydantic 输入输出及 read 方法。范围只能由 Worker 注入，模型/浏览器不能传身份或代码入口。数据库只读事务阻止常规 SQL 误写，配置停用或版本变化后冻结 Run 也不能绕过。LLM 仍走可插拔 JSON 网关，图片生成仍经独立确认；契约与示例见 [项目记忆与只读工具](M2项目记忆与只读工具.md)。

V1.9 可选流式 LLM 协议：stream_complete(messages,on_content,timeout_seconds) 返回 LLMResult。回调只传原生 content，不传推理、HTTP 收据或工具参数；完整返回仍需最终校验。无协议插件沿用 draft/complete，网络失败不能自动补发另一种协议。见 [逐字流式回复](M2逐字流式回复.md)。

## V1.10 配置化需求字段与历史工具

agent.brief_fields 是可信部署配置：key/label/max_length，默认场景、光线、配色、保留项、禁止项；最多 8 项，key 唯一、每项最长 160 字，可置空隐藏字段卡并保留存量数据。服务端返回 field_definitions，前端不硬编码业务字段；模型候选、用户确认和在途配置变化均校验。字段值沿用项目记忆的确认与清理机制。

agent.tools 可独立启用 search_project_history，入口为 app.modules.conversations.history:HistorySearchTool；声明 creative/current_project/read_only、conversations/project_memory 依赖，输入 query/limit，输出有限原话与来源。身份、项目、隐私与遗忘边界由服务端绑定；不支持任意 SQL、网络或跨项目查询。该工具采用 literal_keyword_v1，未来语义检索可另行接入受控插件并增加评测。完整配置见 [第五批说明](M2创作需求卡与历史管理.md)。

## V1.11 知识与客服扩展

knowledge作为独立模块，只要求identity；关闭Agent仍可提供已发布指南。embedding入口和options从可信knowledge配置读取，签名spec/embed(texts,timeout_seconds)，维度、有限值和归一化严格校验。开发哈希必须显式开关且生产拒绝；真实采用302 Qwen3-Embedding-8B的1536维请求，换空间需重建。

只读插件新增get_catalog与search_knowledge，声明creative/support角色、当前项目或公开知识范围。无项目客服只能查公开目录/已发布知识，项目工具仍要求服务端绑定拥有者和隐私。模型不能指定角色、用户或代码入口。知识短引用键由Worker生成，只能解析到本轮真实chunk；证据不足状态不强迫挂无关来源。

Git Release绑定整个后端代码、模型、提示词、图、预算、工具、上下文、目录、检索、向量空间和固定集摘要；生产还需要匹配的真实重复抽样与人工质量审核报告。普通网页配置不能绕过此门禁。详见[完整M2说明](M2完整交付与验收.md)。
