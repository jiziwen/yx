# 四种创作方式 · V1.3

2026-10-22，用户已确认多方式 UI 原型，四种入口已接入正式首页、灵感库及工作室。原型仍保留于 `/preview`、`/preview/library`、`/preview/studio`，正式业务不读取其中示例状态。

## 正式流程

| 方式 | 本次输入 | 提案与任务 |
| --- | --- | --- |
| 拍同款 `template` | 每项一张套系底图 + 明确选中的人物参考 | 按镜头 × 每镜头版本数拆分，逐任务只发送自己的底图；指定人物对应底图位置 |
| 设计写真 `portrait` | 明确选中的人物参考 + 可选的套系风格参考 | 设计新画面，不自动把界面封面作为模型输入 |
| 修改照片 `edit` | 一张已上传底图或本项目已有作品 | 选择保留项并填写修改要求，无需额外人物参考 |
| 从文字开始 `text` | 零图片，只使用画面描述 | 不要求人物槽或上传；不承诺画面人物与用户本人一致 |

首页四个入口由后端公开的 `creation_modes` 过滤。访客可浏览 `/inspiration` 的套系、镜头和用途选择，开始创作时登录、命名项目、确认单/双人类型。选片与初始想法只通过应用内存带入新项目，URL 仅包含目录 ID。工作室共用准备画面、拍摄提案、生成结果；手机通过对话/画布切换。

人物授权和人物参考上传保留现有面板；新上传的照片自动选中，本页可取消本次选用而不删除素材。切换方式保留素材与便签，但编辑/文字方式不会发送人物参考。上传底图必须显式声明有权使用，服务端统一解码、限制尺寸、去除 EXIF 并私密保存。所有私有图片仍经项目拥有者和输入血缘校验。

保存只创建不可变提案与确认卡。提案中任何字段、选用图片、人物对应或项目修订变化后，旧卡关闭确认；确认弹窗展示已保存的逐项输入用途、张数、实际次数消耗与修改范围。确认后才预占并创建 Jobs/outbox。工作室展示真实任务状态和私有交付；开发图片插件的测试卡不会冒充写真。

生成结果可「以此为底图继续修改」。新一代输出只记录本任务实际使用的私有输入，完整祖先血缘用于读取授权校验。撤销祖先照片立即阻断所有后代，维护进程逐代标记和清理。未完成任务取消、未知结果保留预占与禁止盲目重试的规则保持不变。

## 配置位置

| 位置 | 可配置内容 |
| --- | --- |
| `services/backend/resources/catalog.yaml` | 目录版本、风格/套系启停、适用项目类型、镜头列表、人物位置、画幅、单次总张数、开放方式、素材保存上限 |
| `resources/inspiration/` | 本地可信套系素材；不允许客户端传文件路径或外部 URL |
| `services/backend/resources/application.yaml` | 图片插件启停、版本、能力与可选 `image_routes`，未配置操作路由时回退 `routes.image` |
| 图片插件 `capabilities` | `operations`、`max_input_images`、`max_reference_images`、`max_style_images`、`max_subjects`、`aspect_ratios` |
| 兼容图片插件 `options.size_by_aspect_ratio` | 已验证的画幅到像素尺寸映射；必须与声明画幅一致 |
| `apps/web/src/features/atelier/creationModes.ts` | 创作入口文案和图标；不决定服务器可用性或数值限制 |
| `apps/web/src/themes/*/manifest.ts` | 界面外观、布局素材和 token，独立于套系和模型输入 |

后端 YAML 通过校验/重启生效；前端文案和主题通过构建生效。新增套系不要求安装同名界面主题；新增图片供应商遵循 `ImageProvider.generate(ImageRequest)`，不改变工作室业务组件。

套系启动时从配置目录读取，规范化为 PNG，计算 SHA256。公开镜头地址为 `/api/v1/web/inspiration/{style_id}/{shot_id}/content`，不暴露真实路径。当前八张既有图片沿用工作区参考素材的来源记录，标为 `development_only: true`，仅在内测展示并用于开发图片插件；生产环境过滤这些镜头，真实插件也拒绝使用未开放的内测镜头。正式套系应配置已明确可用于生成的授权素材，再移除标志。

## 规格与服务器校验

`POST /projects/{id}/plans` 的新字段：`mode`、`reference_asset_ids`、`base_asset_id`、`shot_ids`、`style_shot_ids`、`style_asset_ids`、`variants`、`keep`、`change`、`subject_bindings`。保留风格 ID/版本、画幅、总张数、氛围、备注和 `expected_revision`。

- 输入图总数按每个交付项计算，底图、人物参考与风格参考共同计数；底图数量不按整套合并。
- 项目里能保存多少照片与模型每次能接收多少照片分开配置，超限不静默截图。
- 位置必须覆盖本次选中的人物，互不重复，并兼容每个所选镜头的 `subject_slots`。
- 非本方式的多余输入被拒绝，不能利用底图或风格参考冒充人物参考绕过用途检查。
- 项目外 ID、无效授权、重复图片、无描述文生图、无底图编辑、不匹配张数、禁用方式或超过模型能力均在保存阶段拒绝。
- 服务端自行编译 schema 2 的 `spec_json.items`，冻结逐项输入、人物授权修订、套系图片摘要和图片供应商配置哈希；客户端不能自行传 items、消耗或上游凭证。
- 接受和外部提交前重新校验输入、权限、样片摘要及冻结供应商。默认路由变化不替换已确认 Job 的供应商。
- 新方案沿用现有 JSON 列与素材 kind 字符串，无 DDL 改动，不需要新迁移。schema 1 历史可读且保留旧请求幂等语义；旧请求未声明 mode 时按原完整人物参考规则保存。四种正式界面全部发送显式模式与本次选中素材。

`ImageRequest` 增加 `operation`、`input_roles`、`subject_bindings`，保留有序图片 bytes 和稳定请求键。兼容候选适配器按 `text` 选择 `/images/generations`，有图选择 `/images/edits`；要求图片直接返回 base64，不下载任意上游 URL。不同供应商的实际协议、人物保持和费用仍需单独验证。

## 2026-10-23：方式随聊天意图转换

四种方式作为执行路径保留，聊天可逐轮改变mode，并迁移已选镜头的base/style用途；不再把当前模式视为固定会话类型。严格换人使用subject_only和独立冻结提示词，保留底图站位、朝向、姿势、构图和色调，不混入旧暖色要求。右侧可以解除严格换人并填写其他变化；生成依然明确确认，输入和模型能力上限继续按路径验证。详见[创作意图与底图保留](创作意图与底图保留.md)。


## 2026-10-26：双栏精简与原图画幅

左侧为会话创意与改图，右侧保留四模式、必要素材、画布和一个确认生成入口。人物/样片/底图/风格参考用弹框选择，高级参数折叠；聊天明确修改可直接更新同一草稿，额外建议仍由用户采用。删除旧 `experience-preview` 路由及示例状态、`CreationMaterials` 重复表单和不再使用的工作室样式，首页和灵感库的共用样式保留。

`aspect_ratio=auto` 表示跟随实际底图，由后端按每个交付项单独计算并冻结 `items[].aspect_ratio`。多镜头可以各自使用不同画幅；人物与风格参考不参与推断，无底图时为3:4。`spec_json.aspect_ratio_choice` 保留原始auto/手动选择，Worker只读取已冻结的实际比例和 `items[].size` 像素尺寸。前端手动选择后，更换底图不会重设，用户可再次选择跟随原图。

尺寸不限，目录中的3:4、16:9、9:16等仅作为常用选项。`auto` 精确保留底图像素宽高，明确比例按默认尺寸换算，也可通过聊天指定宽x高像素尺寸。`integrations/image_sizes.py` 提供默认值与统一的不限尺寸策略；页面、Agent、方案确认及GPT/兼容适配器均不执行画幅白名单、16倍数、面积或最大边长限制。公共能力中的 `arbitrary_size=true` 对历史三画幅发布同样生效，不重写历史供应商定义或已确认任务。
