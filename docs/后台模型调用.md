# 后台模型调用

2026-10-23 实现，2026-10-26 更新弹框、图片任务合并和提示词展示。入口：[本地后台 → 模型调用](http://127.0.0.1:5274/model-calls)。要求独立管理员会话，普通用户和客服员工均不可读取。

## 使用方式

- 图片提交和结果查询按同一任务、同一冻结供应商合并为一行，显示请求数、查询数和累计耗时；不同任务及无任务标识的记录保持独立。先合并再分页，按最近活动时间倒序，每页固定 **20 条**。
- 列表包含时间、类型、实际模型、操作、返回状态、耗时、HTTP 状态和错误分类。
- 点击「查看入参 / 出参」打开弹框，支持关闭按钮、Esc、点击遮罩关闭和关闭后恢复焦点；后台列表保持原位置。
- 弹框优先显示原始提交中的提示词、messages 或 embedding 输入文本，再并列展示真实入参和最近出参；保留供应商插件、用户、项目、Agent Run 和图片任务关联标识。列表不预载正文。
- 「每次请求明细」按每页20次展示提交与轮询；点击某次记录读取该次实际入出参，可随时返回汇总。历史查询ID也能定位对应提交和最近结果。
- 请求和响应从本功能上线后开始记录；原有历史没有请求正文，不能补造。
- `已返回`表示本次插件操作正常返回，不等于最终生成成功。例如图片提交只返回 task_id，后续每次结果查询独立留存但在列表合并；具体任务状态在「生成任务」查看。
- `等待最终记录`表示尚无结束事实，可能正在进行，也可能进程已中断；不能据此自动重发付费调用。

## 记录范围与插件

统一装配在模型网关，覆盖语言/视觉的 draft、complete、stream_complete，以及图片 generate、submit、lookup。保留插件原来的可选协议能力，不给同步插件制造异步能力，不将内部 draft→complete 重复计次。后台更换模型后继续通过同一记录器，历史插件和冻结路由仍有效。知识库 embedding 也通过同一记录器，包括检索查询和索引任务；模型列表查询是配置查询，不属于模型推理调用。

现有兼容 HTTP、302 统一/原生图片和 embedding 适配器补充**实际发送的参数**（model、messages/prompt、质量、尺寸、数量、multipart文件摘要等）和收到的响应（含脱敏错误正文）。新插件即使不提供 HTTP 补充，也会自动留下契约层方法入参与返回值；需要查看实际线路参数时，在适配器调用 `wire_request` / `wire_response`，不应传入认证请求头。

流式回复记录发送的 stream 配置、合并后的 content、finish_reason 和 usage。断流保留已收到的内容并标记失败/未知，无完整请求降级和透明重发。隐藏推理和供应商原生工具思考不进入记录。

开发插件明确标注，不把本地确定性样例称为真实供应商响应；生产环境仍按已有门禁禁止开发插件。

## 数据与隐私

新增 `model_calls`，迁移 `f47d21532c33`，上一个迁移 `f36c10421b22`。每次发送前独立短事务记录调用意图；适配器补充实际HTTP参数后、发送前再次保存提示词和实际模型，返回后更新结果。业务事务回滚不会抹掉外部调用事实。结束日志写失败仅记调用ID，保留未终态记录，不将已完成的远端请求改成可重发失败。有日志数据时拒绝直接有损 downgrade，需明确归档后回退。

- 认证头、密钥字段及当前插件密钥脱敏；不保存可用的带签名URL查询凭证。
- 图片字节、data URL、base64 不复制到数据库，保留省略标记、大小和摘要。
- 每侧JSON有256KB预算，单字符串64K字符、集合200项、嵌套16层，越界明确标记裁剪。记录用于排查，不能直接当作原图或完整供应商报文归档。
- 管理员读取详情写 `model_call.read` 审计，摘要不包含请求/响应正文；日志正文不进入普通审计或用户聊天。
- 模型调用关联用户/项目及隐私代次。账户删除、项目删除或授权代次变化后，详情立即屏蔽旧正文；项目/账户清理会擦除正文，调用期间发生撤销时迟到回包不能重新写回旧正文。知识库公共索引任务没有客户项目范围。
- 记录仅用来观察调用，不改变图片生成确认、权益扣除、任务结算与模型发布规则。

## API

- `GET /api/v1/admin/model-calls?page=1`：返回合并后的 items、page、page_size=20、total、total_pages。每项新增 call_count、lookup_count、latest_at、latest_operation；latency_ms 为累计请求耗时，HTTP/错误状态来自最近操作。page 为1到1,000,000的整数，超出总页数返回空items。
- `GET /api/v1/admin/model-calls/{call_id}?calls_page=1`：合并元信息、最初 request、最近 response、scrubbed 及二者来源 request_call_id/response_call_id；calls 为按倒序固定20条的操作元信息，附 calls_page/calls_total_pages。
- `GET /api/v1/admin/model-calls/{call_id}/payload`：仅该次操作的元信息及实际 request、response、scrubbed。未收到响应时 response 为 null，不伪造上游返回。两个详情接口都校验管理员和当前项目授权并写读取审计。

## 验收

1. 在工作室发一条聊天，等待回复；后台刷新后查看语言模型调用，核对 messages、模型、回复和关联项目。
2. 在工作室主动确认生成，后台同一任务只出现一行。打开弹框核对提示词、模型和 low/其他已发布质量参数，再展开每次请求明细查看提交和查询各自的实际参数。仅聊天不会自动出图。
3. 切换后台发布的模型后再次调用，新记录使用新插件，历史记录保留旧模型。
4. 超过20个独立调用/图片任务后翻页，每页20条；同一任务超过20次轮询仍只占一行，明细单独翻页。验证弹框关闭、Esc、遮罩、焦点恢复与窄屏显示。
5. 上游401/超时/断流仍有记录，入参可见；HTTP错误或已收流片段可见，不重复发送。
6. 普通用户/客服无法读取；删除项目或撤销授权后，旧详情不再展示正文。
