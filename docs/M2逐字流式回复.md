## 体验与恢复

- Lumi 回复时出现“正在回复”气泡，文字来自本轮真实模型 content 的 reply 前缀。没有前端打字定时器，也不承诺模型每次返回恰好一个汉字；网络、供应商缓冲及数据库采样可能合并多个字符。
- 临时内容仅展示可见 reply，工具参数、proposal JSON、候选记忆、隐藏推理不流进气泡。追问列表、查询事实卡、记忆建议与提案在校验后的最终消息中展示。
- 临时气泡不能应用方案或确认生成；最终内容可能因格式修正或校验与临时版本不同。失败、取消、超时或授权变更会移除临时内容，不把半条回复伪装成成功消息。
- 断线、刷新或回到前台后读取权威会话快照。仍在生成时可恢复最新前缀；已完成则恢复单条最终消息，不重复模型请求、不重复追加文字。临时历史不逐 token 回放。
- 每次模型调用单独编号 attempt_no；已有的最多一次格式修正属于新尝试，清空旧前缀。旧连接、旧尝试、重复/逆序片段和旧隐私代次不能接入新回复。
- 画布提示位于聊天历史之前，避免新增回复被后置提示挤出可视区域。临时气泡关闭逐字屏幕阅读器播报，最终消息沿用会话日志的可访问性语义。

## 模型协议与可插拔配置

可选协议 `StreamingLLMProvider.stream_complete(messages, on_content, timeout_seconds) -> LLMResult`：供应商原生 content 到达时回调，最后返回完整 JSON 对象与数值用量。既有 `draft` / 可选 `complete` 仍兼容；没有流式方法的插件按完整响应工作，不模拟逐字显示。

CompatibleLLM 使用 `/chat/completions` 的 stream=true、JSON 输出约束和 stream_options.include_usage。HTTPX 在事务外逐帧读取 SSE，处理 UTF-8 分片、多行 data、心跳、结束与用量；只消费 choice 0 的 delta.content，忽略 reasoning_content 和原生工具字段。总原文最多 65536 字符，最终 finish_reason 必须 stop；没有有效结束、连接中断或错误事件按结果未知处理。

协议依据：[302 流式 Chat 文档](https://doc.302.ai/api-235272987)、[HTTPX 流式读取](https://www.python-httpx.org/quickstart/#streaming-responses)。当前只读工具仍由应用自己的 JSON 工具循环实现，没有向供应商提交通用原生工具参数。

```yaml
agent:
  streaming_enabled: true
  stream_flush_ms: 120
conversation_stream:
  enabled: true
  poll_seconds: 2
  delta_poll_seconds: 0.2
  heartbeat_seconds: 15
  max_connection_seconds: 240
```

agent 开关/节流随新 Run 冻结；stream_flush_ms 50–1000。delta_poll_seconds 为活跃 Run 的短读取间隔，0.1–1 秒；空闲仍使用原 poll_seconds。供应商可信 options.streaming_enabled=false 可以独立关闭其流式能力，改用原完整调用；后台模型名称和预算无需更换。选路和能力由服务端插件控制，浏览器不能指定密钥、URL 或编排入口。

关闭会话通知后，快照仍可恢复最终消息及当前前缀，显示频率降为既有轮询。没有 SSE 就不承诺实时逐字体验。已有运行的旧冻结预算没有 streaming_enabled 字段时继续原完整调用。

HTTP 断流、SSE 协议异常或不明结果不会自动改发完整请求，也不重发流式请求。完整返回但模型 JSON/提案校验失败仍适用既有的一次结构修正、最大调用预算和总期限。取消立即撤销本地发布权并清除临时内容；上游已开始的调用不保证立即停费。每次网络读取和每次前缀写入检查期限，最终提交再检查；等待首字/网络无数据时仍受底层读取超时约束，维护进程终止逾期本地 Run。

## 持久化与 SSE

迁移 `a38f94cce1d2` 在 AgentRun 新增可空 stream_json。内容为当前 Run 的 `{run_id, attempt_no, seq, text, privacy_epoch}`；text 最多 1200 字符，seq 在同一次调用内递增，只保留最新前缀，不建 token 历史表。旧 Run 字段为 null，旧消息不改写。升级前备份 `.data/agent-streaming/main-before-a38f94cce1d2.db`。

ReplyPublisher 从不完整 JSON 中解析顶层 outcome/reply，只在已识别合法 outcome 后公开 reply；完整转义、Unicode 代理对和嵌套字段均有边界处理。不用正则匹配任意 reply 字段。模型输出顺序不符合前缀约束时，等待完整校验，不伪造进度文字。

每批前缀短事务按项目→会话→Run 加锁，检查执行令牌/调用编号、用户/项目状态、隐私、需求、记忆、素材和总截止时间；网络等待不持有事务。默认最多约每 120ms 写入一次变化前缀。最终消息与 Run 终态在同一事务提交并清除 stream_json；取消、失败、超时和隐私清理也清除。临时文字不进入后续历史上下文。

RunView 新增可空 reply_preview，GET 会话/Run 均限拥有者和当前隐私代次。`message.delta` 信封新增 run_id、attempt_no；resource_revision 为当前尝试的 seq。payload 包含 privacy_epoch、preview，清除时 preview=null，终态附 closed=true。preview 是累计整段前缀，客户端按序替换，丢一帧不会丢字；不是在旧字符串后盲目追加。

订阅 ready 后发送当时已有的前缀，随后比较跨 API/Worker 的数据库状态；每次读取继续复核会话/项目/隐私权限。正式 message.committed/run.updated 仍只驱动权威快照失效，现有低频校准、退避重连、前台恢复和代理无缓冲配置继续有效。此实现仍需后续连接容量/数据库负载压测，尚无媒体事件总线。
