# M2.5 单人写真质量闭环：最终方案、风险与验收清单

日期：2026-10-23。状态：**Q1–Q19 已逐项确认，用户已确认整体方案并授权完整开发；工程交付记录见 [M2.5 完整交付与验收](M2.5完整交付与验收.md)，真人测试尚未执行。**

同日用户新增要求：简化项目内选图至生成步骤，左侧对话完成四种创作，右侧同步展示，加入计划后一并开发。已纳入[对话式工作室与流程简化](M2.5对话式工作室与流程简化.md)，本轮已纳入实施；下文对应操作流程与实施顺序已同步调整。

用户进一步明确：右侧必须保留四种方式的完整手动创作流程，全程不聊天也可完成选图、参数调整、确认生成和继续修改。左右两侧共享草稿、确认单与结果，可随时切换；手动操作不自动调用聊天/视觉模型，任一侧确认一次即可。

本轮先证明“用户能得到像本人、符合所选主题的满意写真”，再扩大场景。现有 M2 功能与工程记录继续有效，但不等于人物效果、费用或上线质量验收通过。本方案补 M1 人物效果/成本验收、M2 视觉分析与发布门禁，并前置必要的 M3 质量反馈/补偿能力；不声称完成整个 M3。

本文只规定本轮范围和验收方法。整体确认不替代每次图片生成及补偿重做的用户确认，也不授权无监督付费回归。当前已进入实现与隔离验证；本次开发未调用收费接口。

## 2. 用户看到的完整流程

1. 选择已审核可用的单人主题。素材来源、处理用途和版本有记录，未放行的套系不用于真实生成。
2. 明确选用本次人物参考，记录测试者知情同意和供应商处理说明。
3. Lumi 通过对话追问、整理提案；已确认的项目要求继续有效。
4. 聊天内补齐素材和必要参数，右侧同步展示。应用层自动准备经过服务端校验的冻结方案，在同一张卡中展示输入、张数及次数消耗；用户点击一次最终确认后才创建图片任务，省去重复的手动写入/保存及二次弹窗。
5. 交付真实结果和真实任务状态；未知提交继续核对原请求，不盲目重发。
6. 用户点击“帮我看看”，选择要分析的图像。只有这次列出的图片进入视觉请求，不遍历项目库存。
7. Lumi 给出有来源的分析和修改建议，区分观察、推测与无法判断的部分；不把建议冒充客观相似度百分比。
8. 用户在聊天中引用作品继续修改，画布显示候选差异；新方案自动准备后，用户再次明确确认才生成。主观不满意可另行反馈；人工补偿也走同一明确确认流程。

已有分析可以在当前授权范围内作为带来源的历史文字使用，不冒充对新版本图片的观察，也不因此后台重发图片。把分析中的偏好写为长期要求仍需用户明确确认。

## 3. 真人样本与主题准备

- 由用户组织三位成年、自愿参与的测试者，使用本人提供的照片；明确告知生成、视觉分析及所用供应商。
- 先核验现有原创单人样片的来源与展示、衍生、模型处理用途，能够确认后复用；不足时再制作新样片。删除 `development_only` 标记不构成授权或效果验收。
- 选择两个正式可用单人主题，冻结主题/样片摘要、输入用途、图片模型及质量档位、提示词和视觉配置。
- 基本样本为 **3 人 × 2 主题 × 2 张 = 12 张**，编号 B01–B12，覆盖不同脸型和参考照条件。先校验每项输入符合模型实测上限，再执行对应样例。
- 测试者独立评价本人辨识度，用户评价风格、明确保留项和可交付性；保留评分理由与失败分类。
- 原始失败保留，补偿、重试和诊断调用另列；不能用重做成功覆盖首次失败，也不能只挑最好的一张算整组通过。
- 测试授权只覆盖本轮。宣传展示、训练、后续评测复用均不自动获得授权；现有用户项目不充当默认测试集。

这是建立基线的小样本实验，不支持“所有人/所有主题/所有模型效果已验证”的结论。质量通过率、允许波动和时延上限在实测后由用户明确批准，当前不预填数字，也不以做满 12 张自动判定通过。

## 4. 100 元预算与费用核对

本轮新增实验的**规划总预算为人民币 100 元等值**，包括对话、视觉、图片、embedding、失败/诊断/重做，以及必要的新样片制作等真实调用。历史消耗单列，不混入本轮时间窗，也不据此声称历史费用为零。

1. 使用独立 302 测试 Key；密钥仅写服务端秘密配置，不放进聊天、浏览器、源码或验收报告。
2. 每批执行前列清样例、模型/质量、数量、预算依据与未确认费用；原始币种、实际扣费和折算依据分开记录。
3. 维护调用清单，按供应商实际记录逐批人工核账；其他工具费用也单列，不用共享账户余额差直接代替本轮费用。
4. 区分估算、实际和未知成本。费用无法确认时暂停下一批，核对后再决定是否继续；不把未知视为零，也不自行追加预算。
5. 计划 12 张不优先于预算/授权/故障停止条件。预算不足时记录“未完成/待处理”，不为凑满样本而继续调用。

**100 元是实验预算，不是现有系统能保证的金额硬封顶。** 上游扣费可能迟到，已提交请求不一定能取消；先停新的相关调用并核对在途费用，不保证已发生费用可以追回。若以后需要严格金额上限，另做可靠的费用预占、结算与供应商限额验证。

## 5. 照片、分析、记忆与删除

### 5.1 两类操作明确区分

| 操作                      | 确认后的产品语义                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 取消本次选用              | 修改后续方案输入，不删除照片，不改变既有生成授权                                                                                       |
| 真正删除素材/撤销人物授权 | 删除前列出影响范围；立即阻断新的相关访问与调用，清理相关原图、派生成片、分析和旧上下文，处理在途及迟到结果                             |
| 保留通用文字偏好          | 用户可明确选择保留已经确认、脱离图像仍成立的通用偏好，例如“喜欢暖色光”；不保留图像观察、人物识别信息或隐含图像证据，不从旧聊天自动恢复 |
| 删除项目/账户             | 相应范围的照片、分析及偏好一并清理，不适用上述保留选项                                                                                 |

删除仍按项目隐私代次清理较大范围的聊天和记忆；M2.5 已补明确选择已确认通用偏好的迁移，校验原记忆版本与隐私代次，不从历史对话或图像分析自动重建。原撤销与血缘阻断继续保留。

### 5.2 本轮保留期限

- 本轮隔离测试中的照片、成片、可识别分析及评测副本默认自导入/产生起保存 **30 天**，提前可删除；需要延期时重新取得测试者同意，不静默延期。
- 临时文件、缓存和备份副本也纳入清理清单与期限；恢复备份不能恢复已撤销素材的可访问性。未落实备份到期规则前，不把到期清理标为通过。
- 可保留去除个人识别信息的评分、故障和费用统计，不能保留可重新关联到测试者的照片引用充当匿名记录。
- 该期限仅针对本轮隔离测试数据，不自动过期或删除现有用户项目。正式对外用户数据保留策略仍属于未来开放前的独立事项。
- 本地删除不等于上游已删除。[302 公开隐私政策](https://302.ai/legal/privacy/)没有给出所选图片/视觉 API 的固定照片保留期限；真实测试前核对对应模型的数据处理范围，向测试者说明已确认与未确认部分，不承诺上游零留存或即时删除。

## 6. 反馈、补偿与人工服务

- 初期由用户本人或指定管理员查看留言，界面明确“非实时客服”，不承诺固定响应小时数。
- 留言待领取时机器人可继续帮助；撤回留言不等同解决问题。员工实际领取时切入人工，阻止迟到自动回复。
- 用户可退出已领取的人工会话；服务端使旧员工窗口的迟到回复失效，保留记录，回到机器人后不自动重放旧消息或触发图片生成。
- 工作人员默认不能看图。用户可授权指定成片，必要时另勾选一张参考照作对照；不因此获得整个项目或全部原图权限。
- 查看请求重新校验会话、工单、图片与授权；撤回授权或结单后阻止新访问。访问凭据及有效期纳入验收，不承诺收回工作人员已经看过的内容。
- 同一质量问题人工确认后最多补偿重做一次，重复提交不重复发放。补偿是新任务、保留原结果和审核记录，不扣用户新增权益，但计入本轮真实预算。
- 变更风格等新需求使用新方案；技术失败和未知提交继续遵守现有权益/核对规则，不混作主观质量补偿。Agent 不决定退款、补偿或自动重生成。

## 7. 模型与主题的候选验收、启用及回退

保存配置→候选→按对应能力测试→用户审核→启用。后台填写能力参数或模型列表出现名称，不代表该能力已通过。

- 验收按实际使用场景和输入限制记录：单人/双人、同款/设计/编辑/文字、视觉分析分别判断；本轮通过只覆盖实测范围。
- 视觉模型独立配置模型、输入张数/尺寸与请求预算、适配协议和可用状态；不支持时显示不可用。具体模型依据能力核验和实测确定，不让用户猜接口能力。
- 主题/镜头版本和样片摘要绑定对应测试证据；界面外观主题仍独立配置，不强制与写真套系同名，也不影响冻结方案。
- Release 门禁补查完整必测题集、逐题重复次数与结果、原始失败、候选摘要、批准人及质量/费用证据，拒绝只有批准标签或只跑单题的报告。
- 测试中修改代码、模型或主题后按受影响范围重新验证，累计费用继续计入 100 元；保留此前报告，不以成功覆盖失败。
- API/Worker 使用一致的实际执行版本。启用/回退不擅自替换已确认任务的冻结输入和模型；未知提交只核对原请求，不换通道重新付费。
- 测试者评价本人辨识度；用户负责最终产品验收和启用批准。我整理工程与模型证据，不替代用户签署质量通过。
- 预算异常、授权失效、明显身份错误或关键工程约束失败时先暂停相关新调用；问题处理后由用户批准恢复。暂停不等于已停止远端任务，仍须处理在途记录。

- [ ] “帮我看看”只发送本次列出的图片，记录图像/版本、分析模型、用途和用量；无视觉能力时显示不可用。
