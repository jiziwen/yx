## 已接入的业务路径

正式工作室的拍同款、设计写真、修改照片、从文字开始共用原有方案→确认→预占→Job/outbox。图片网关同时支持两类协议：

- 同步 `generate(ImageRequest) -> ImageResult`：供现有开发插件与通用兼容 HTTP 插件使用。
- 异步 `submit(ImageRequest) -> ImageSubmission(task_id)`、`lookup(task_id, request_key) -> ImageLookup`：302.AI 使用此协议；其他厂商新增适配器即可，无需改工作室。

Worker 先在数据库保存稳定请求键和 `submitting` 尝试，再提交一次。接单凭据提交到数据库后，后续只查询原任务。默认不发送未经上游确认支持的幂等 Header，也不宣称本地请求键能让上游去重。

`pending` 保留预占；明确 `failed/cancelled` 才释放；成功经过图片规范化、授权/血缘复核后发布私有 Asset 并结算一次。同步和异步共用同一个发布函数。Worker 崩溃、提交响应丢失、查询失败、未知状态、任务 ID 不匹配、结果下载失败均保留待核对事实，不重发生成。已有凭据可继续恢复；没有凭据的未知提交需要供应商记录人工核对，暂不提供强制成功/退款或手填远端 ID 的入口。

用户在远端执行期间撤销授权后，迟到图片不会发布。远端成功与实际费用记录保留，用户次数按授权失效返还。用户点击取消已经提交的任务只记录取消请求；当前 302.AI 插件没有确认过的远端取消能力，成功结果仍按现有取消语义结算。

本地 Worker 与 Celery scheduler 都会调度原任务查询。消息只包含本地 Job ID，远端凭据、照片和密钥不进入消息体。查询租约避免多个 Worker 同时查询同一项；发布事务/终态检查防止重复交付。

## 302.AI 配置

当前推荐通过后台 /models 发布版本，已按用户选择启用 gpt-image-2 / low 和 claude-sonnet-5-5。密钥已完成连通性验证，文生图真实生成与语言模型短 JSON 调用已通过；单/双人身份和账单效果仍待验收。详见 [后台模型配置](后台模型配置.md)。下方 YAML 是部署候选模板，保持默认关闭；已有数据库发布优先于模板路由。

官方依据：[统一异步生成](https://doc.302.ai/337661604e0)、[异步获取结果](https://doc.302.ai/337672611e0)、[当前模型入口说明](https://doc.302.ai/)。协议于 2026-10-22 核对；模型标识与输入上限仍须用实际账号、选定模型验证。

已注册 `app.integrations.ai302:AI302Image`，默认 `enabled: false`，避免误发付费请求。默认候选模型为 `gemini-3.1-flash-image-preview`，可分别配置 text/reference/edit。默认候选限额为总输入 3、人物参考 2、风格参考 1、人物 2；这些是保守的联调范围，不是身份效果验收结果。

1. 在 `services/backend/.env` 设置 `AI302_API_KEY`，或向后端进程注入同名环境变量。显式环境变量优先，密钥不能写进 YAML 或前端。
2. 复制完整 `resources/application.yaml` 到受控配置目录，通过 `CONFIG_FILE` 指向该文件；保留模块与其他 routes。
3. 将 `ai302-image.enabled` 设为 true，`routes.image` 改为 `ai302-image`。或者用 `image_routes` 只对某些操作切换。
4. 按 302 控制台实际模型修改 `options.models`，按实测修改 capabilities。默认状态 `release_status: candidate` 仅供开发联调，生产必须先完成验收再明确设置 `validated`。
5. 重启 API、Worker 和 scheduler，重新保存方案后确认。冻结配置变化时旧方案不会被悄悄换模型。

```yaml
# 以下是已有 ai302-image 条目的关键字段，不是完整应用配置。
runtime:
  account_scope: ai302-main
  max_in_flight: 2
  requests_per_minute: 10
  poll_seconds: 5
  failure_threshold: 3
  cooldown_seconds: 60
options:
  base_url: https://api.302.ai
  api_key_env: AI302_API_KEY
  models:
    text: gemini-3.1-flash-image-preview
    reference: gemini-3.1-flash-image-preview
    edit: gemini-3.1-flash-image-preview
  result_hosts: [file.302.ai, file.302ai.cn]
```

提交地址固定为 `/302/v2/image/generate?run_async=true`，图片以按角色排序的 data URL 数组 `image` 直接发送，不把私有参考照变成公开链接。查询地址固定为 `/302/v2/image/fetch/{task_id}`。结果仅允许受控的公共 HTTPS 文件主机，不跟随重定向，下载不携带供应商令牌且最多 30 MiB，再由业务图片规范化检查。结果 URL 不交付给前端。

当前目录里的内测套系镜头不能发送给真实插件。文生图可先联调；写真/编辑使用已获授权的私有上传；拍同款需在 catalog.yaml 配置有生成用途授权的正式镜头。勿直接把 development_only 改为 false 代替取得授权。

## 运行保护与费用

本批使用共享 PostgreSQL 的 `runtime_gates` 行锁协调所有 Worker，SQLite 用于本地测试；不引入第二套 Redis 媒体锁。数据库无法协调时，新付费调用不会发生。此为原文档“V1 可用 Redis”的一种替代实现。

相同供应商账号的多个模型必须配置相同 `account_scope`，并声明相同并发、分钟速率及熔断参数，否则启动失败。`submitting/pending/unknown` 全部占在途槽，本地租约到期不释放。分钟窗口限制实际提交次数，查询不计入新生成次数。持续调用失败后暂停新提交，冷却后放行探测；HTTP 429 的 Retry-After 单独保存，不被其他在途成功提前清除。本阶段每项交付最多一次生成提交，不做透明付费重试或自动备用供应商。

入口 `queue_limits` 默认：单批 8、单用户待处理 16、总待处理 500。在短事务的全局入口锁下先校验，再预占权益并创建 Jobs；容量拒绝不消耗请求键，容量恢复后可复用原键。待核对计入待处理量。调度按用户轮转，在有界扫描内避免单个用户的一批占满本轮。

调用表记录本地稳定请求键、接单凭据、状态/错误、查询时间、终态耗时、数值用量、估算/确认费用与各自币种。金额使用整数微单位。估算来自可信 runtime 配置，不是实际账单；缺少真实费用就是 null。302 统一响应尚未确认可靠账单字段，当前仅提取数值 token/image_count 白名单，实际成本保持未知。未实现严格金额预算预占、账单对账导入和完整成本聚合。
