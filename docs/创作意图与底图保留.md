# 聊天创作意图与底图保留

2026-10-23：修复「只替换人物」实际以风格参考重新设计写真、导致站位及构图改变的问题。

## 交互规则

四种方式是可随需求切换的执行路径，不是锁定会话的四套流程。用户可在同一聊天中从拍同款切到新写真、改为纯文字创作、再对已选底图做微调；右侧也可直接切换。模式、素材用途、补充要求、输入能力限制和确认卡应同步更新，聊天本身不提交图片任务。

| 用户意图 | 执行路径与输入 |
| --- | --- |
| 只替换已选样片中的人物，其余保持原图 | template / 拍同款：第一张为样片底图，后续为人物身份参考；subject_only=true |
| 带人物照片，重新设计场景、姿势或构图 | portrait / 设计写真：人物为身份参考，样片可选作氛围参考；subject_only=false |
| 微调已选上传底图或已生成作品 | edit / 修改照片：一张已选私有底图，只修改明确要求 |
| 不使用参考图，从文字创作 | text / 文字创作：实际请求不包含图片输入 |

对“只替换人物”“把人物替换就行了”等无歧义短指令，服务端有保守兜底；复杂表述、否定、疑问和所指底图不明确仍由LLM理解及追问。不能只改聊天回复而保持原mode。未选样片时不猜图，未选私有素材不可擅自加入。当前单底图编辑路径不自动获得额外换人人物照片输入权限，能力不支持或指代不清时明确处理。

跨方式切换时：已有风格参考转为底图要迁移到shot_ids，反向转为风格参考则迁移到style_shot_ids；保留用户实际选的镜头，不回到默认第一张。显式空数组表示清空，切换套系不携带旧套系镜头；人物照片和已选上传底图保留为可复用草稿选择，只有当前方式的实际输入会进入方案。普通编号换片不改变当前模式。

## 严格换人约束

`subject_only=true`只适用于template。样片为权威底图，人物参考仅提供身份，不借用其站位、姿势、衣服、光线或背景。提示词明确保留底图的站位、身体/头部朝向、视线、姿势、手势、人物占比、相机距离和角度、构图、背景、服装、光线、曝光、白平衡和色调，禁止镜像、拉近、裁切和重构场景。

严格换人有独立提示词分支，不混入旧mood/notes中的“更温暖、柔光、重新设计”等指令。右侧展示对应保留规则，便签与氛围同步为保留底图，并暂不可编辑以免显示与实际执行不一致。用户可在右侧取消「只替换人物，保留底图其他细节」，或在聊天中明确提出新意图，由Agent把subject_only设为false并更新方式/要求。严格换人不是永久模式锁。

## 实现与冻结

- DraftPatch增加可选subject_only；DraftContext默认false兼容旧JSON。PlanInput接受subject_only，省略时template默认true，其他方式为false；非template声明true会被拒绝。SpecView返回subject_only及prompt_version。
- `agents/transitions.py`在提案校验中衔接目录用途；前端`transitionDraft`供聊天和右侧按钮共用。私有素材归属、用途、人物位置和授权依然独立验证。
- `creation_prompt`是可信部署级提示词插件配置：entrypoint、version、options。默认`app.modules.executions.prompts:compose`、版本`creation-v5-zh`，不与302模型名称、质量档位或主题素材配置绑定。系统添加的指令全部使用中文，只描述画面及必要的图片用途、人物位置；不发送套系标签、上传路由说明、内部ID或空角色字段。用户要求的外文画面文字保持原样。
- 新方案保存时逐交付项冻结实际prompt、prompt_version及策略摘要，纳入content_hash。Worker直接发送冻结文本，不在确认后重新拼接提示词；更换编译插件不修改已确认任务。
- 旧未确认方案缺少prompt_version时要求重新准备确认卡，前端会自动准备；旧已确认任务保留原执行语义，不在部署时偷偷改变。补偿重做继续沿用原方案的冻结输入和提示词。
- 原请求幂等键在调用方没有提供subject_only时保留旧语义，不因新增默认字段改变重试结果。无数据库结构迁移。
- 兼容LLM仅接受完整JSON或包住完整JSON的标准代码围栏；不从附带正文、XML或其他代码中提取对象，所有Agent字段和权限校验仍执行。格式异常沿用既有的一次受预算限制的格式修正，图片调用没有透明重发。

图片仍使用后台已发布的gpt-image-2 / low，本次不提升质量档位、不修改供应商路由。最终成片的站位保留效果需要用户再次明确确认出图后观察；工程测试验证实际模式、输入顺序、提示词和确认边界，不能冒充真实图片效果验收。

## 验收步骤

1. 设计写真中选一张样片与人物参考，聊天输入“把人物替换就行了”。右侧应切为拍同款，同一张样片被选为底图，人物参考不丢；保留规则开启，旧暖色说明被替换。
2. 检查确认卡：base在前、person在后，subject_only=true。后台模型调用的图片提交可核对实际prompt，不应有“Design a new portrait”或旧暖色要求。
3. 不点击生成时无新图片Job、无预占次数。确认后只创建对应一次任务；质量仍low。
4. 继续说重新设计新场景/新姿势，Agent应解除严格换人约束；改为纯文字时不发送原参考图，改回编辑时只使用先前明确选中的底图。
5. 右侧直接切换也遵守同样的用途迁移。刷新可恢复，旧确认卡在草稿变化后失效；显式清空和跨套系选择不能被默认图覆盖。
6. 模型能力不支持、素材缺失、权利未开放或人物位置不明确时，保持生成边界并给出原因，不绕过确认。
