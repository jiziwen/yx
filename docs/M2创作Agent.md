## 用户操作

1. 在左侧描述想法，或回答 Lumi 的问题。模型与真实处理阶段显示在对话区域。
2. 需求不明确时显示追问；足够明确时显示“为你整理的拍摄提案”，列出建议修改的方式、套系、氛围、画幅、张数或完整创作要求。
3. 点击“写入草稿”才修改右侧表单。等待期间修改了草稿或项目资料，旧建议不能覆盖新修改，需要基于当前草稿重新整理。
4. 检查素材、授权及能力限制，手动保存正式提案，再通过原有确认卡启动图片生成。对话中说“立即生成”也不会创建 Plan、Approval、Job 或权益流水。

对话保存在当前项目，刷新可恢复。未写入/未保存的表单编辑仍属于页面草稿。一次只处理当前会话的一条消息，忙时返回 AGENT_BUSY。失败保留用户消息，提供重新编辑入口；停止后迟到的模型回复不会发布。

## 配置与可插拔边界

- 后台 `/models` 发布语言模型 ID 与单次输出预算；新消息选择该版本，已入队 Run 保留原模型 ID/版本/配置摘要。切换模型不会自动重放旧消息，也不会更改图片模型。
- `resources/application.yaml` 启用 conversations、agents 及 `features.chat_enabled`。两模块可禁用，历史表仍保留。关闭功能不启动新调用，右侧提案表单继续可用。
- `agent.entrypoint` 指向可信服务端编排函数，默认 `app.modules.agents.graph:run_graph`。更换编排与更换 LLM 适配器相互独立；浏览器不能指定 Python 入口、模型端点或凭证。
- 默认总期限从入队起计 90 秒；默认最多 3 次模型调用、4 次只读工具尝试，格式/来源最多修正一次。上下文 12000 字符、最近 6 个完整成功轮次、配置模型窗口 64000 tokens，保留配置输出预算与 1024 tokens 安全余量。换成更小窗口模型时同步调低 `agent.context_window_tokens`；必要上下文本身超限会拒绝，不静默丢弃当前要求。
- 同一用户最多 4 个待处理 Run、全局 100 个；每个 provider 的 runtime 决定并发、分钟速率、熔断和退避。具有相同 account_scope 的图片与语言调用共同占用槽位；未声明共享 scope 的配置独立计量。通道不可用时本轮明确失败，用户手动重试，不后台反复调用。
- 无真实 LLM 配置时使用显式标记的 local-llm 开发样例，仅复制原话以验收链路，不能将其视为真实理解。密钥仍只在后端 .env/环境变量。

LangGraph 使用“理解 → 校验 → 可选一次修正”的短图，按实际执行步骤更新状态；参考[官方固定流程与 Agent 组合说明](https://docs.langchain.com/oss/python/langgraph/workflows-agents)。没有依赖托管服务或持久化 checkpoint；显式关闭对话 tracing 外发。

## 上下文与权限

固定只读来源为 get_project_context、list_styles、get_selected_materials，均由服务器绑定当前用户/项目，不接受模型提供身份。V1.7 已开放可配置的次数/任务只读工具循环；无写工具。当前草稿完整保留，历史按完整轮次从近到远纳入预算；当前表单中的已确认限制优先。长期要求需经用户确认后独立持久化，不能从普通聊天自动晋升；V1.10 已增加可配置结构化需求卡与有来源的关键词历史查询。

本批不向 LLM 发送照片字节、对象键、下载 URL 或人物姓名，只传用户文字、当前表单和选中素材的用途/尺寸/人物 ID。私有 ID、用途、授权及多代血缘进入模型前逐个验证；跨项目请求统一拒绝。旧隐私代次的消息立即隐藏且不再进入模型，维护进程清除其正文、提案和冻结上下文。

模型草稿仅允许 mode/style_id/aspect_ratio/count/variants/mood/notes/change/keep。不能修改素材、人物位置、授权、价格或供应商；结构/目录/画幅/数量/输入能力校验失败最多修正一次，仍无效则失败且不发布半成品回复。正式保存和确认仍由已有业务服务重新校验全部素材、能力与权益。

## API 与持久化

| 接口 | 行为 |
| --- | --- |
| GET `/api/v1/web/projects/{id}/conversation` | 最近 60 条消息、30 个 Run、当前模型与可用性；读取不调用 LLM |
| POST `/api/v1/web/projects/{id}/messages` | text、client_message_id、expected_revision、draft，202 返回 Run |
| GET `/api/v1/web/agent-runs/{id}` | 当前运行事实、模型与来源草稿 |
| POST `/api/v1/web/agent-runs/{id}/cancel` | 原子撤销最终提交权，幂等 |

迁移 `b9ff639728f2` 添加 conversations、messages、agent_runs。每项目一个创作会话；消息序号唯一，消息键与原始正文摘要保证防重。同一会话不接受多个未完成 Run。Run 本身兼任可靠投递意图，由调度器重扫 queued，不需要第二条 outbox 事实。

入队、领取和提交按 Project → Conversation → Run → 必要容量/账号 gate 的顺序短暂持锁。网络调用在事务外；调用次数先落库，返回后复核唯一 token、取消、账户/项目状态、brief_revision、privacy_epoch、素材及当前图片目录能力。取消时在途槽位仍保留至调用返回或调用期限；进程崩溃后不自动再次花费 LLM 调用，超时明确失败。

## 运行和验收

`pnpm dev` 同时启动独立 API、图片 Worker、Agent Worker 和两个前端。单独本地启动：`uv run python -m app.workers.agent`。生产 Celery 需额外运行 agents 队列，scheduler 重投递 Run ID；maintenance 负责超时及隐私清理。Redis 消息不含需求正文或照片。

无付费工程验收：`pnpm check:m1` 继续覆盖全部现有回归，并纳入 Agent 合约、浏览器持久化/草稿冲突与 PostgreSQL 竞争测试。它不是完整 M2 产品质量验收。

需显式真实模型验收时，在后端目录执行 `uv run python -m evals.agent_smoke --live`。脚本读取后台已发布的非敏感模型配置，创建隔离数据库和静物需求，执行两轮“追问 → 提案”，断言 Plan/Approval/Job 均为零；不会上传用户照片或调用图片模型。
