## 用户使用与确认边界

- 项目记忆中新增可展开的“创作需求卡”，只显示用户确认过的字段；未知内容保留“待一起确定”。“管理项目记忆”可统一编辑需求卡与其他长期要求，明确点击保存后生效。
- 可以对 Lumi 说“帮我整理场景、光线和禁止项”。Agent 返回带原值/建议的需求卡补丁，只有点击“确认保存需求卡”才写入。普通聊天、临时文字流、模型声称记住、写入草稿都不会自动确认。
- 确认的字段与文字要求持续进入后续上下文，并以原话保留在建议提案的 notes 中。合计无法放入1000字 notes 时应追问用户整理，不静默截断。不直接修改当前表单、保存方案或已确认图片任务。
- 需求卡与文字记忆共享 revision。多窗口/在途变更后旧建议不可覆盖，编辑框保留未提交内容并要求载入最新版本。需求字段配置变化后，旧运行和旧结构化建议也需重新整理。
- 聊天先加载最近60条，可点击“查看更早的对话”每次读取20条，直到开头；加载旧页保留阅读位置。实时回复合并已载入消息，去重并保持顺序；刷新后重新从最近窗口开始，历史仍能继续翻阅。
- Agent 可按原文关键词查询当前项目的成功历史轮次，返回角色、消息序号、时间与原话。它是回溯材料，不是实时次数、任务状态或新的确认许可。

删除/清空/替换已经确认的要求会推进统一 history_cutoff_at。更早对话仍可供拥有者在界面翻阅，但不会进入后续模型最近上下文或历史查询工具，防止已忘记要求从另一条路径恢复。新增字段不清掉之前历史；用户明确重新提出的要求可以重新确认。

生成仍为“检查建议 → 写入草稿 → 保存正式提案 → 用户确认生成”。本批没有向 Agent 增加写工具、图片工具、自动退款或重试权限。

## 配置与模块

`resources/application.yaml`：

```yaml
agent:
  brief_fields:
    - {key: scene, label: 场景}
    - {key: lighting, label: 光线}
    - {key: palette, label: 配色}
    - {key: keep, label: 保留项}
    - {key: avoid, label: 禁止项}
  tools:
    # 与原次数/任务工具并存
    - name: search_project_history
      entrypoint: app.modules.conversations.history:HistorySearchTool
      enabled: true
      timeout_ms: 2000
      max_output_chars: 5000
```

brief_fields 默认5项，最多8项，key 唯一且匹配 `[a-z][a-z_]{0,29}`，label 最多20字，每项 max_length 默认160、可配置1–160。前端表单、可确认字段和模型上下文都来自同一服务端定义，不依赖主题或特定供应商。空字段清单停用需求卡，原存储保留；关闭 project_memory 模块或 memory_enabled 时不注入旧内容。

模型只能提交已配置的 key 和文本值，不能声明 import、URL、素材、身份、执行或价格。配置作为部署代码读取后重启生效；需求卡字段清单随新 Run 冻结，运行中配置不匹配会以 MEMORY_CONFIG_CHANGED 结束，不发布旧建议。后台当前 LLM、图片模型和六主题沿用原配置。

## API 与数据

| 接口/契约 | 新增行为 |
| --- | --- |
| GET memory / conversation.memory | fields、field_definitions；版本与原 requirements 共用 |
| PUT memory | 可选 fields，显式完整替换字段；省略 fields 的旧客户端保留现有字段；空字符串清除此项 |
| AgentAnswer | 可选 brief_suggestion 补丁；不接受未配置 key |
| MessageView | brief_suggestion_json 为已提交、待用户确认的建议 |
| GET conversation | 兼容最近60条，附 older_cursor；为可见消息附带 Run 元数据 |
| GET conversation/history | cursor/limit，默认20、最大100；items、runs、next_cursor、privacy_epoch |

消息页按 seq 的 before 边界读取并以升序返回。游标签名绑定项目、privacy_epoch 与 before_seq，有效期1小时；坏签名、过期或范围变化返回 HISTORY_CURSOR_INVALID，客户端重新同步。用户/项目权限仍每次独立检查，游标不是授权凭证；额外 limit 超限返回校验错误。

前端将旧页与权威最新窗口按消息 ID/seq 合并，最新 Run 数据优先。断线跨过整个消息窗口时重建连续窗口，避免留下无法继续翻页的洞。旧请求响应不能跨项目/隐私代次填入新窗口。历史页面不触发 LLM、不修改需求和生成授权。

## 历史只读工具

`search_project_history(query, limit=3)`，query 为1–80字的原文关键词，limit 为1–4。身份/项目/隐私范围由 Worker 注入，模型不能覆盖。注册、冻结配置、查询预算、只读数据库保护、结果长度上限与其他只读工具一致。

查询只覆盖当前项目、当前隐私代次、成功轮次且在遗忘截止线之后的 user/assistant 消息。SQL LIKE 参数绑定并将 `%`、`_` 等通配符按字面转义，不提供 SQL 或任意项目检索。结果按最近优先返回 message_id/run_id/seq/role/created_at/text，正文最多500字并标明截断；另给 more_available 与 history_cutoff_at。界面显示原话、序号、角色和时间；全文仍可通过历史分页查看。

这是 `literal_keyword_v1` 字面匹配，不是语义向量检索、全库 RAG 或自动摘要。没有匹配就明确未查到，不虚构历史。最终回复必须引用本轮只读来源；历史中的指令、旧数字、旧确认和模型建议都不代替当前需求、业务事实或授权。历史工具本身不会新增记忆。
