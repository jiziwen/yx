# M2.5 对话式工作室与流程简化

2026-10-23。用户要求将工作室流程简化、左侧聊天完成创作、右侧同步展示并入 M2.5，一起实施。本轮已获用户授权开始完整实施，代码与验收见 [M2.5 完整交付记录](M2.5完整交付与验收.md)。配套范围、100 元预算和真人验收仍见[单人写真质量闭环方案](单人写真质量闭环方案与验收.md)。

## 1. 改版前的问题及证据

- `StudioGuide.tsx` 的提案操作仍为“写入草稿”，然后通过 `onPlan` 切换右侧页面；对话不能完成素材选择与最终确认。
- `StudioPage.tsx` 同时暴露准备画面、拍摄提案、生成结果三个视图，以及人物参考面板、保存提案、已保存提案区和最终确认弹窗。
- 典型聊天提案路径需要“写入草稿→保存新提案→满意，确认创作→弹窗确认”，多次操作围绕同一方案。
- 试用领取、素材不足、人物授权等分散在不同位置，用户要自行判断下一步。
- `agents/schemas.py` 的 `DraftPatch` 只允许部分字段建议，不支持素材/镜头引用；仅修改前端按钮不足以实现对话创作。
- 草稿主要由页面状态持有，聊天、手动修改和已冻结方案存在多套展示；新增实时联动需要共同版本与恢复策略。

## 2. 目标体验

**表达需求并补齐必要素材 → 查看一张完整确认卡 → 确认生成 → 就地查看结果、继续修改。**

左侧是完整的聊天创作入口：文字、上传/选择素材、主题候选、少量追问、提案确认、任务操作和作品引用。右侧是完整的手动创作入口与同步画布：可点击选择方式、主题、素材，编辑参数与修改要求，确认生成，查看结果并继续修改。保留现有梦幻视觉、圆角与主题 token；常用创作控件直接可见，高级参数收进“调整细节”。

两侧是平等、可独立使用的入口，共享同一个当前创作状态。用户全程不发聊天消息，也能在右侧完成四种创作；不必先让 Agent 整理提案，也不因手动选图、改参数而自动调用聊天或视觉模型。LLM 不可用时，手动路径仍可使用。

### 右侧独立操作路径

| 方式       | 全程在右侧完成的操作                                           |
| ---------- | -------------------------------------------------------------- |
| 拍同款     | 选主题/镜头→上传或选择人物参考→调整张数/画幅→检查确认卡→生成   |
| 设计写真   | 选人物参考和可选风格参考→填写场景/氛围→检查确认卡→生成         |
| 修改照片   | 选上传底图或已有作品→填写保留项/修改要求→检查确认卡→生成       |
| 从文字开始 | 填写画面描述→调整张数/画幅→检查确认卡→生成，无需人物资料或图片 |

右侧结果区“修改这张”直接进入右侧编辑流程；另提供“和 Lumi 聊这张”或“帮我看看”作为可选 Agent 入口。用户可以先右侧选图再左侧描述，也可以先聊天再右侧微调，无需重复输入或重新建方案。

在素材、权限、权益都齐备且用户需求明确的常规路径中，整理完成后只要求**一次最终生成确认**。必要的素材授权、歧义消解、领取试用和主动选择建议仍如实呈现，不以隐藏这些动作虚报“一键完成”。不再要求手动跨标签写入、另点保存、再重复弹窗确认。

## 3. 四种方式在聊天中完成

| 用户表达示例                     | 左侧操作与必要追问                                                 | 右侧同步画面                                     |
| -------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| “按这套拍两张我的写真”           | 主题卡选择套系/镜头，选已有本人参考或就地上传；仅补问缺失用途/人物 | 套系与参考缩略图、镜头/张数/画幅、待确认同款方案 |
| “用我的照片设计一组柔光写真”     | 选人物参考，可选风格参考；整理场景与氛围，默认值可见可改           | 人物参考、风格方向和设计方案                     |
| “把这张背景改成海边，人物别动”   | 引用一张上传图或本项目作品；指代不明确时要求选图                   | 底图、保留/修改项，生成后可比较修改前后          |
| “生成一张淡紫色花园，不需要人物” | 直接文生图；不要求上传、不要求人物资料、不自动携带历史照片         | 文字画面说明、画幅/张数及待确认方案              |

创作方式由需求和明确输入推断并在卡片标示，用户可纠正，不强制先答一套模式问卷。开放方式、主题及输入限制继续来自后端能力目录；没有该能力时说明原因并提供可用选择，不暗中切换。

四种方式都接对话操作与工程回归；本轮 12 张真实效果验收仍只覆盖单人同款，不自动扩展真人测试和预算。

## 4. 素材与追问就地处理

- 聊天输入区支持上传和选择本项目素材/作品，所选图片以附件缩略图列出用途：人物参考、底图、风格参考。人物声明与必要授权放在素材卡内完成。
- 用户在右侧选中作品后，“修改这张”“作为参考”可直接在右侧继续操作；“和 Lumi 聊这张”“帮我看看”才进入相应聊天/分析流程。显示本轮目标，不因后台新结果到达而改变引用。
- “这张”“第二张”只绑定用户当时看到并选定的具体资产；多个可能对象时提供缩略图选择，不能让模型猜任意资产 ID。
- 用户明确选择/上传用于本轮的素材可直接进入当前可撤销草稿。Agent 推荐的额外素材先展示候选，由用户选定，不能擅自选用历史私照。
- 新上传完成后根据此次用途直接选用，不要求再去另一面板重复勾选；上传失败保留输入，允许就地重试。
- 只询问阻止生成的缺项，相关缺项集中在一个卡片中；已有有效授权、已选素材和已确认要求不重复问。
- 清晰的文字创作不进入图片授权步骤；创作选图不等于视觉分析授权。“帮我看看”继续遵守主动触发与明确发送范围。
- 权益不足时在同一确认卡附近提供可用的试用领取入口或具体提示，不跳离工作室，不假装已领取，也不自动发放未经配置的权益。
- 长期记忆保存保持可选、显式确认，不作为每次出图的必经步骤。

## 5. 合并提案操作，保留一次真实确认

用户明确表达的修改，例如“改成横版、只出一张”，经白名单和版本检查更新当前可撤销草稿，画布展示变更。模型主动提出的替代方案先作为候选预览，保留手动编辑，允许采用或撤回；不把流式未完成输出直接写入有效状态。

聊天候选或右侧手动输入完成并通过校验后，由应用层自动准备服务端冻结方案和确认卡；省去“写入草稿”“保存新提案”两个常规必经按钮。手动方案直接由业务服务校验与编译，无需等待 LLM。冻结不生成、不预占权益，未完成或失败的模型输出不能自动准备有效确认。

确认卡展示：创作方式、主题/镜头、实际选图及用途、人物对应、保留/修改项、画幅、张数、将消耗的次数和必要的规格说明。候选与当前状态有差异时同卡展示。“按此方案生成 · N 张 / X 次”是最终明确动作，不再叠加内容重复的确认弹窗。

左右两侧都展示可操作的确认卡与生成按钮，共用同一确认单 ID、版本和提交状态。用户在任意一侧确认一次即可，另一侧同步为执行中，不需要再确认，也不能重复创建任务。输入、授权、主题或规格变化立即使两侧旧卡失效，重新准备后再供用户确认。

聊天中输入“生成吧”可打开/定位对应确认卡；“好的”、模型说“正在生成”或历史消息不作为支付动作。只有用户对当前完整确认卡的明确操作调用既有确认 API。

应用层沿用服务端 Plan→Approval→Job 的业务约束。LLM 提供结构化意图与候选字段，不能自行授权、选择任意资源、接受确认单、扣次数或执行图片。自动准备和最终确认使用独立的幂等与版本保护；准备成功、确认响应丢失时查询原状态，不重新生成一份付费请求。

## 6. 右侧同步展示与恢复

| 阶段            | 画布展示与规则                                                                           |
| --------------- | ---------------------------------------------------------------------------------------- |
| 补素材          | 当前选图、缺项与可用主题；可局部编辑，不强制跳转独立准备页                               |
| 整理方案        | 已完成校验的候选内容与差异，标明准备中；原生流式文字只在聊天显示，不把半截 JSON 当作方案 |
| 待确认          | 服务端准备完成的同一确认卡对应画面；未获服务器确认前按钮不可执行                         |
| 生成中          | 每张真实任务的排队/生成/待核对/失败状态；上游没有百分比或预览图时不制造进度或假成片      |
| 部分完成        | 成功一张就显示一张，其他任务继续更新；取消、失败与待核对各自保留                         |
| 已完成/继续修改 | 作品可下载、选中引用、看图分析、再次修改；新版本保留来源，不覆盖原作                     |

“实时”指已有状态和结果及时反映到画布，不承诺上游持续输出中间图。先复用现有任务轮询与会话 SSE，抽象统一同步边界；是否扩展媒体事件由实现必要性决定，不为此提前建设完整事件平台。

聊天、手动编辑、草稿与候选方案使用统一版本来源和恢复契约。当前创作草稿需私有持久化，刷新后恢复；不得将私照或敏感需求塞进 URL/localStorage。多窗口或在途回复发生冲突时保留用户较新编辑、展示可采用的候选，不静默覆盖。

新结果到达只更新对应任务组，不抢走正在查看旧作品或编辑新方案的焦点；显示新结果提示供用户切换。手机使用“聊天创作 / 手动创作”两种视图和紧凑状态提示，共用同一状态；任一视图均能独立走完完整流程，无需反复切页。

## 7. 接口和模块规划

- 复用工作室、对话、项目、素材、执行、任务及现有网关模块，不另建一套聊天出图后端。
- 扩展受控创作意图契约：模式、可见候选的主题/镜头引用、明确附件/作品引用、修改字段、缺项及来源版本。后端独立解析资源、校验归属/用途/授权/模型能力，拒绝模型编造的引用。
- 素材上传及选用由用户交互调用确定性业务 API；LLM 的只读工具权限不因此升级成任意写入权限。
- 引入共享的当前创作状态与私有草稿恢复，区分用户编辑、模型候选和服务端冻结确认；用版本/请求键处理自动准备、冲突及重连。
- 整合 `StudioGuide`、`CreationMaterials`、`SubjectPanel`、`StudioResults` 与 `StudioPage` 的操作入口；右侧保留完整的模式、素材、常用参数、确认和作品操作，仅高级参数折叠，两侧共享同一状态。
- 四种方式的必需输入、提示卡、可用操作通过已有模式配置与后端能力组合，避免在聊天里写死供应商、主题或图片数量。
- 工程步骤、版本摘要留在必要的详情入口；普通创作只展示用户可理解的需求、素材、规格、消耗与状态。

## 人工体验验收修正（2026-10-23）

用户实际体验后明确调整：**左侧以聊天为主，右侧负责素材、参数、提案和生成确认**。此条取代早期“两侧各放一套完整表单”的界面方案；聊天仍可理解四种创作需求并整理右侧草稿，右侧仍可全程不聊天完成创作。

- 移除聊天流中的完整创作表单、结果列表、确认卡及重复引导按钮；记忆与运行信息折叠。视觉选图只有用户主动展开时显示。
- 普通明确要求可整理当前方式的可撤销草稿；LLM 建议切换创作方式时，先展示右侧候选和差异，用户采用后才切换，不因收到回复自动跳到拍同款。候选采用继续检查草稿、需求、记忆和隐私版本。
- 私有草稿完成载入前显示准备状态，避免先渲染默认方式再跳到已存方式。
- 右侧独立滚动，底部固定显示生成按钮、张数、次数及阻塞原因。即使缺素材、次数不足或冻结方案失败，按钮仍可见但禁用；不把真实模型拒绝内测样片变成“按钮消失”。
- 对设计写真选用了内测风格参考的情况，提供明确的取消参考操作；不会自动替换用户输入，不会绕过样片审核。拍同款仍要求已审核样片。
- 当前用户项目仅检查和刷新页面，没有提交聊天、调用真实模型、领取权益或生成照片。保留原草稿和作品。

## 目录选图指代与供应商错误修正（2026-10-23）

人工反馈暴露了已实现字段与实际交互之间的缺口：Agent上下文虽有目录镜头ID，但私有已选素材与右侧套系图库缺少明确的用途/编号/选中关系，导致“风格参考换第二张”被误解为需要第二张上传人物照。

- 目录事实及`get_catalog`共用镜头元数据和从1开始的`display_position`，顺序与右侧`style.shots`一致，不依赖某个主题名或固定模型。
- 每轮冻结当前`selection.active_catalog_gallery`，明确`source/role/target_field/style_id`及每个镜头的编号和选中状态。portrait使用`style_shot_ids`，template使用`shot_ids`；私有人物参考/修改底图单独记录，明确`materials`只包含已选私有素材，不能据此断言项目或右侧只有一张图片。
- 用户明确要求“换成第二张、第一张不要”时，返回目标字段的完整替换数组，直接更新可撤销草稿；仅明确追加时保留原项。保持未涉及的方式、套系、人物参考、便签和参数，不要求重复上传目录图片或重复确认人物授权。无图库、编号越界或用途歧义时追问；不能假装观察过图片。
- 服务端仍校验镜头所属套系、私有素材范围与模型能力，迟到回复仍受草稿/记忆版本屏障保护。选择开发样片是可撤销编辑，与允许真实生成分开；最终生成仍检查审核与能力并由用户确认，选图不会创建Job或消耗出图次数。
